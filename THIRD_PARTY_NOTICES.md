# Third-party notices

## Purpose and scope

This file records notices for third-party material incorporated into Synaptik and identifies
separately supplied native runtime dependencies. It does not select or describe a project-wide license.

The Cephes notice below applies only to the error-function (ERF) coefficient tables and
piecewise rational approximation in:

- `modules/backend/cpu/src/main/java/io/github/pho001/synaptik/backend/cpu/internal/codegen/emit/CpuScalarEmitter.java`

Synaptik's Java implementations are adapted realizations of that approximation. Generated scalar

source file or Cephes library is bundled.

## Cephes provenance

The coefficient tables and piecewise ERF/ERFC approximation are derived from Stephen L. Moshier's
Cephes `ndtr.c`. The original [Netlib Cephes documentation](https://netlib.org/cephes/doubldoc.html)
identifies the ERF and complementary error function (ERFC) routines and their rational
approximations. The current [SciPy XSF `ndtr` source](https://github.com/scipy/xsf/blob/main/include/xsf/cephes/ndtr.h)
retains the same coefficients, algorithm family, and original Cephes source header. XSF's
[bundled-license inventory](https://github.com/scipy/xsf/blob/main/LICENSES_bundled.txt) publishes
the permission and notice reproduced below and identifies its Cephes distribution as
`BSD-3-Clause`, distributed with the author's permission.

Synaptik commit `9dec4cb7` first introduced the tables and reference ERF realization. Commit
`73ecd053` explicitly identified them as Cephes `ndtr.c` coefficients. Commit `949b8413` adopted
that ERF realization across the closed portable unary matrix, and commit `e0ae213f` duplicated the
same tables and evaluation shape for self-contained generated bytecode.

Exact coefficient matches alone do not establish a redistribution path or license. These Cephes
tables have also been redistributed inside projects under reciprocal licenses, so fingerprint-
based scanners can associate the same numeric sequence with those projects. Repository history
shows Synaptik's reference realization and later direct-bytecode realization as Cephes-derived;
it does not identify a GPL-licensed project as their source. This is a provenance record, not legal
advice.

## Distribution responsibilities

CPU binaries and source distributions containing the material above must carry the Cephes notice,
conditions and disclaimer. Independently redistributed generated `.class` or persistent `.artifact`
outputs, or exported oracle/evidence sources, require accompanying notice materials too. A local
generated-code cache is not a standalone redistribution policy; its binary schema is unchanged.

Current native Metal ERF/GELU use Apple's MPSGraph implementation, not the retained CPU Cephes
approximation. The native package does not bundle Apple frameworks, an OpenBLAS implementation,
oneDNN or a JDK. Their installed runtime distributions have their own applicable terms. This distinction
does not supply a project-wide license for Synaptik's own Java/native/shader material.

## External oneDNN runtime

The opt-in CPU integration binds the public C interfaces of externally supplied oneDNN 3.14.0
through the JDK Foreign Function and Memory (FFM) API. No oneDNN source or binary is bundled
in Synaptik artifacts. The upstream pinned [`v3.14` license](https://github.com/uxlfoundation/oneDNN/blob/v3.14/LICENSE)
is Apache License 2.0 and identifies additional component terms in
[`THIRD-PARTY-PROGRAMS`](https://github.com/uxlfoundation/oneDNN/blob/v3.14/THIRD-PARTY-PROGRAMS).
Deployers or redistributors supplying that library must retain the license, applicable attribution/
notice material and component terms required by their exact oneDNN distribution. This entry
does not replace those materials or license Synaptik itself.

The [CPU integration guide](docs/backend-guide/cpu-backend.md#external-binary-and-loading-requirements)
records the exact source/build pin and required sequential CPU configuration. A CI download/build
of upstream oneDNN is separate from bundling a native runtime in published application artifacts.
