# ADR 0048: Dense actual read views in CPU general scan

## Status

Accepted — 2026-10-24; implemented with focused qualification in
[CPU0037](../../planning/backends/cpu/tasks/0037-general-scan-dense-read-views.md).
Main accepted the final capability gates on 2026-10-24.
The user approved the narrow CPU extension (“ok, pust se do toho”), not fluent RNN migration.
This record explains the coordinated root/scan-owner decision; it is not architecture authority.

## Context

Before this decision, the homogeneous FLOAT32/FLOAT64 CPU general-scan binder admitted canonical
actuals and zero-offset all-zero-stride scalar reads. Its dense-read check compared the entire
layout descriptor, including the view flag. A source-grounded NN0032 audit found two cases whose
addresses are already dense but which fail only this read-layout distinction: Conv1d's final
singleton-axis removal before an RNN Scan, and the actual reverse seed generated by singleton
CONCAT on a Scan output. The ordinary unrolled RNN route admits those workflows.

For sequence shape `[3,2,4]`, strides `[8,4,1]` and offset zero, changing only `isView` does not
change any of the 24 cell addresses. The audit established old/new provider/Compiler admission
and bounded forward results, not backward numeric correctness. CP0013 separately closed bounded
body persistence; it did not authorize `.rnn` migration or resolve this CPU execution gap.

## Decision drivers

- Admit that exact same-address read geometry without weakening write or formal requirements.
- Preserve source descriptors, view metadata/equality, storage ownership and lifecycle guards.
- Keep existing scalar broadcasts and generated constants working without materialization.
- Qualify real forward and actual reverse execution, not assume closure from supported children.
- Avoid new APIs/types, emitter/IR/identity churn and unrelated migration or timing work.

## Options considered

1. Keep full-descriptor read equality. This retains the demonstrated source compatibility gap.
2. Admit only dense, canonical-stride zero-offset actual read views alongside existing reads.
   This uses the same address/access/resource path and leaves formal/write validation intact.
3. Insert CONTIGUOUS or clear view metadata upstream. Copies add work and metadata rewriting
   changes observable descriptors; outer CONTIGUOUS also lacks the needed cold persistence admission.
4. Support arbitrary affine reads or relax canonical checks globally. This requires wider
   addressing/qualification and risks accepting views at write/formal boundaries.

## Decision and rationale

Choose option 2. The detailed permission belongs only to the
[scan owner's declared qualification](../../architecture/contracts/recurrent-scan.md#traversal-empty-domains-and-declared-qualification),
indexed by the [root invariants](../../../ARCHITECTURE.md#core-invariants).
All actual read roles in the existing pointwise/shaped/MATMUL families, including actual Compiler
reverse occurrences, receive the same narrow proof. Canonical non-view formals and outputs remain
unchanged. Existing all-zero-stride reads are a separate retained case, not constrained by the
dense-stride test. Bounds, storage, overlap, lifetime and role validation remain exact.

The current lowering has one read-specific predicate shared by pointwise and shaped analysis;
no evidence requires another production concept. Implementation is bounded to that admission
seam. A need to change physical binding, emitters, IR, schema or cache identity requires a stop
and main decision, not silent expansion.

## Consequences

### Positive

Dense reads can keep their truthful view metadata and ordinary source provenance without a copy.
The same code and resources can serve canonical twins; existing scalar reads remain efficient.

### Costs and limits

This adds an independently qualified capability, not permission for offsets, arbitrary strides,
unresolved layouts, low types or unsupported bodies. Tests must distinguish reads from formals
and writes. The small admission diff still requires Class C review and integration evidence;
source compatibility cannot be inferred from a synthetic descriptor alone.

### Migration, testing and follow-up

CPU0037 must demonstrate canonical-twin access/resource/IR/identity/class-byte equality, real
Conv1d-prefix forward/actual reverse and singleton-CONCAT-seeded reverse numeric gradients versus
independent ordinary unrolling, plus focused empty/carrier/reuse/alias guards. With generated
code and binding unchanged, reuse CPU0036's specialized clean-Java/Class-File/performance evidence
with its limits; no new benchmark or speed claim. Main owns final module/conformance/integration
and one configured root checkpoint using the existing native library, with performance flags off.

Implementation review on 2026-10-24 confirms the read-specific predicate and unchanged formal/write
guards. Focused tests pass for real Conv1d-prefix and singleton-CONCAT actual reverse workflows,
with outputs and connected gradients compared to ordinary unrolling in both dtypes and traversals.
Eighteen canonical/view pairs preserve full lowering facts, identities, generated bytes and cached
artifact reuse; generator and physical binding remain unchanged. This evidence supports the
bounded CPU0036 evidence reuse above, not a new performance claim. Main accepted the final gates
and capability on 2026-10-24; fluent migration remains independently gated.

NN0032 remains Draft: preserving absent versus canonical cold output descriptors, initialization,
state aliases, workflow compatibility and separately approved fluent migration authority are not
implemented by this decision. Fixed/static routes and all other owners remain unchanged.
