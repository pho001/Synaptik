# [ADR](../../glossary.md#term-architecture-decision-record-adr) 0048: Dense actual read [views](../../glossary.md#term-view-meanings) in [CPU](../../glossary.md#term-cpu) [general scan](../../glossary.md#general-differentiable-scan)


## Editorial reading context

The backend reads an actual Tensor bound to a Scan formal. A Tensor view describes addresses in existing storage, unlike a diagnostic report view. Here the admitted actual read can carry a view flag while retaining dense zero-offset addresses. That does not relax output writes, formal descriptors, arbitrary strides or storage lifetime checks.

Use the [dense reads and their qualification limits](../../architecture/general-differentiable-scan.md#dense-actual-reads-implemented-final-gates-pending) for focused guidance. The original status, decision
and evidence below remain historical records; this reading aid does not amend them.

### Mathematical reading aid: unchanged dense addresses

For the stated shape, let integer coordinates satisfy $0\le t<3$, $0\le b<2$
and $0\le f<4$. The zero-offset element address is $a(t,b,f)=8t+4b+f$, in
elements from the storage base. Thus $a(2,1,3)=23$, the last of 24 cells. Changing
only a view flag leaves this mapping unchanged. Byte addresses additionally multiply
by the element width; this example does not admit nonzero offsets or arbitrary strides.

## Context

Before this decision, the [homogeneous](../../glossary.md#term-homogeneous) [FLOAT32](../../glossary.md#term-float32)/[FLOAT64](../../glossary.md#term-float64) [CPU](../../glossary.md#term-cpu) general-[scan](../../glossary.md#term-cumulative-scan) binder admitted [canonical](../../glossary.md#term-canonical-form)
actuals and zero-offset all-zero-[stride](../../glossary.md#term-stride) [scalar](../../glossary.md#term-scalar) reads. Its dense-read check compared the entire
[layout](../../glossary.md#layout) [descriptor](../../glossary.md#term-descriptor), including the [view](../../glossary.md#term-view-meanings) flag. A source-grounded NN0032 audit found two cases whose
addresses are already dense but which fail only this read-layout distinction: Conv1d's final
[singleton](../../glossary.md#term-singleton)-[axis](../../glossary.md#term-axis) removal before an [RNN](../../glossary.md#term-recurrent-neural-network-rnn) Scan, and the actual reverse [seed](../../glossary.md#term-seed) generated by singleton
CONCAT on a Scan output. The ordinary [unrolled](../../glossary.md#backpropagation-through-time-and-recurrent-state) RNN route admits those workflows.

For sequence [shape](../../glossary.md#shape) `[3,2,4]`, strides `[8,4,1]` and offset zero, changing only `isView` does not
change any of the 24 cell addresses. The audit established old/new provider/[Compiler](../../glossary.md#term-compiler) [admission](../../glossary.md#term-admission)
and bounded forward results, not backward numeric correctness. CP0013 separately closed bounded
body [persistence](../../glossary.md#term-persistence); it did not authorize `.rnn` migration or resolve this CPU execution gap.

## Decision drivers

- Admit that exact same-address read geometry without weakening write or formal requirements.
- Preserve source [descriptors](../../glossary.md#term-descriptor), [view](../../glossary.md#term-view-meanings) [metadata](../../glossary.md#term-metadata)/equality, storage [ownership](../../glossary.md#term-ownership-meanings) and [lifecycle](../../glossary.md#lifecycle) guards.
- Keep existing [scalar](../../glossary.md#term-scalar) broadcasts and generated [constants](../../glossary.md#term-constant) working without [materialization](../../glossary.md#materialization).
- Qualify real forward and actual reverse execution, not assume closure from supported children.
- Avoid new APIs/types, emitter/[IR](../../glossary.md#term-intermediate-representation-ir)/[identity](../../glossary.md#term-identity-meanings) churn and unrelated migration or timing work.

## Options considered

1. Keep full-[descriptor](../../glossary.md#term-descriptor) read equality. This retains the demonstrated source compatibility gap.
2. Admit only dense, canonical-stride zero-offset actual read views alongside existing reads.
   This uses the same address/access/resource path and leaves formal/write validation intact.<span data-glossary-navigation="true"> ([canonical glossary](../../glossary.md#term-canonical-form); [stride glossary](../../glossary.md#term-stride); [views glossary](../../glossary.md#term-view-meanings); [validation glossary](../../glossary.md#term-validation))</span>
3. Insert CONTIGUOUS or clear view metadata upstream. Copies add work and metadata rewriting
   changes observable descriptors; outer CONTIGUOUS also lacks the needed cold persistence admission.<span data-glossary-navigation="true"> ([CONTIGUOUS glossary](../../glossary.md#term-contiguous); [metadata glossary](../../glossary.md#term-metadata); [persistence glossary](../../glossary.md#term-persistence); [admission glossary](../../glossary.md#term-admission))</span>
4. Support arbitrary affine reads or relax canonical checks globally. This requires wider
   addressing/qualification and risks accepting views at write/formal boundaries.<span data-glossary-navigation="true"> ([qualification glossary](../../glossary.md#term-qualification))</span>

## Decision and rationale

Choose option 2. The detailed permission belongs only to the
[scan owner's declared qualification](../../architecture/contracts/recurrent-scan.md#traversal-empty-domains-and-declared-qualification)<span data-glossary-navigation="true"> ([scan glossary](../../glossary.md#term-cumulative-scan); [owner glossary](../../glossary.md#term-owner); [qualification glossary](../../glossary.md#term-qualification))</span>,
indexed by the [root invariants](../../../ARCHITECTURE.md#core-invariants).
All actual read roles in the existing [pointwise](../../glossary.md#term-pointwise)/shaped/[MATMUL](../../glossary.md#matrix-multiplication--matmul) families, including actual [Compiler](../../glossary.md#term-compiler)
reverse occurrences, receive the same narrow proof. [Canonical](../../glossary.md#term-canonical-form) non-[view](../../glossary.md#term-view-meanings) formals and outputs remain
unchanged. Existing all-zero-[stride](../../glossary.md#term-stride) reads are a separate retained case, not constrained by the
dense-stride test. Bounds, storage, overlap, [lifetime](../../glossary.md#term-lifetime) and role [validation](../../glossary.md#term-validation) remain exact.

The current [lowering](../../glossary.md#lowering) has one read-specific predicate shared by pointwise and shaped analysis;
no evidence requires another production concept. Implementation is bounded to that [admission](../../glossary.md#term-admission)
seam. A need to change physical [binding](../../glossary.md#term-binding), emitters, [IR](../../glossary.md#term-intermediate-representation-ir), [schema](../../glossary.md#term-schema) or [cache](../../glossary.md#term-cache) [identity](../../glossary.md#term-identity-meanings) requires a stop
and main decision, not silent expansion.

## Consequences

### Positive

Dense reads can keep their truthful [view](../../glossary.md#term-view-meanings) [metadata](../../glossary.md#term-metadata) and ordinary [source provenance](../../glossary.md#term-source-provenance) without a copy.
The same code and resources can serve [canonical](../../glossary.md#term-canonical-form) twins; existing [scalar](../../glossary.md#term-scalar) reads remain efficient.

### Costs and limits

This adds an independently qualified capability, not permission for offsets, arbitrary [strides](../../glossary.md#term-stride),
unresolved [layouts](../../glossary.md#layout), low types or unsupported bodies. Tests must distinguish reads from formals
and writes. The small [admission](../../glossary.md#term-admission) diff still requires Class C review and integration evidence;
source compatibility cannot be inferred from a synthetic [descriptor](../../glossary.md#term-descriptor) alone.

### Migration, testing and follow-up

CPU0037 must demonstrate [canonical](../../glossary.md#term-canonical-form)-twin access/resource/[IR](../../glossary.md#term-intermediate-representation-ir)/[identity](../../glossary.md#term-identity-meanings)/class-byte equality, real
Conv1d-prefix forward/actual reverse and [singleton](../../glossary.md#term-singleton)-CONCAT-seeded reverse numeric [gradients](../../glossary.md#term-gradient) versus
independent ordinary [unrolling](../../glossary.md#term-unrolling), plus focused empty/[carrier](../../glossary.md#term-storage-carrier)/reuse/[alias](../../glossary.md#aliasing-and-arena) guards. With generated
code and [binding](../../glossary.md#term-binding) unchanged, reuse CPU0036's specialized clean-Java/Class-File/performance evidence
with its limits; no new benchmark or speed claim. Main owns final [module](../../glossary.md#term-module)/[conformance](../../glossary.md#term-conformance)/integration
and one configured root [checkpoint](../../glossary.md#term-checkpoint) using the existing [native library](../../glossary.md#term-native-library), with performance flags off.

Implementation review on 2026-10-24 confirms the read-specific predicate and unchanged formal/write
guards. Focused tests pass for real Conv1d-prefix and singleton-CONCAT actual reverse workflows,
with outputs and connected gradients compared to ordinary unrolling in both [dtypes](../../glossary.md#data-type--datatype) and traversals.
Eighteen canonical/[view](../../glossary.md#term-view-meanings) pairs preserve full [lowering](../../glossary.md#lowering) facts, identities, generated bytes and cached
[artifact](../../glossary.md#term-artifact) reuse; generator and physical binding remain unchanged. This evidence supports the
bounded CPU0036 evidence reuse above, not a new performance claim. Main accepted the final gates
and capability on 2026-10-24; fluent migration remains independently gated.

NN0032 remains Draft: preserving absent versus canonical cold output [descriptors](../../glossary.md#term-descriptor), initialization,
state aliases, workflow compatibility and separately approved fluent migration authority are not
implemented by this decision. Fixed/static routes and all other [owners](../../glossary.md#term-owner) remain unchanged.
