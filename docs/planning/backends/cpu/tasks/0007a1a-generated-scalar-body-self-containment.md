# Task 0007A1A: Generated Scalar-Body Self-Containment

## Status

Complete

## Goal

Make every covered schema-29 scalar generated body self-contained with respect to Synaptik
production helpers: generate the existing scalar activation formulas, BFLOAT16 cumulative-scan
arithmetic, and aggregate extrema/Boolean combination directly into the generated class while
preserving exact current semantics, layouts, carriers, ranges, lifecycle behavior, and performance.

Retain `CpuVectorMath` as the intentional narrow chunk-level Java Vector API boundary unless a
concrete benchmark fails. A vector body's scalar tail is generated by `CpuScalarEmitter` and must
satisfy the same scalar self-containment gate as a scalar-only body.

## Scope

- Replace per-element generated calls from `CpuScalarEmitter` to `CpuScalarReferenceKernel` for
  `ERF`, `SIGMOID`, `GELU_EXACT`, `GELU_TANH_APPROXIMATION`, and `SILU` with direct generated
  formulas that preserve the current exact/default algorithms, constants, operation order,
  widening/narrowing points, special-value behavior, and raw result bits.
- Replace per-element generated calls from `CpuScanEmitter` to its BFLOAT16 `addBfloat` and
  `multiplyBfloat` helpers with direct widen-to-FLOAT32, typed add/multiply, and existing
  round-to-BFLOAT16 bytecode for `CUM_SUM` and `CUM_PROD`.
- Replace per-element generated calls from `CpuAggregateEmitter` to its FLOAT64, FLOAT32,
  BFLOAT16, INT32, INT64, and BOOL combination helpers with direct generated MIN/MAX/ALL/ANY
  selection or combination bytecode. Preserve NaN selection, signed-zero selection, signed
  integral comparison, canonical BOOL behavior, and empty identities exactly.
- Cover scalar-only pointwise bodies, vector bodies' scalar tails, dense integer-address bodies,
  typed general long-address bodies, primitive-array carriers, `MemorySegment` carriers, mixed
  carrier patterns, arbitrary legal invocation subranges, and existing parallel orchestration.
- Add stable automated member-reference tests over representative generated artifacts for every
  covered family, type, access form, and scalar-tail route.
- Advance `CpuGeneratorSchema.CURRENT_VERSION` exactly once, from 29 to 30, only after generated
  class bytes change. Update current-only persistence/cache compatibility tests; do not add a
  migration reader.
- Record complete `javap -c`, `javap -v`, class checksum, descriptor, and extracted member-reference
  evidence beneath one fresh `/private/tmp/synaptik-cpu-0007a1a-*` directory.
- Run fixed direct-primitive-Java comparative probes for every changed former-helper category and
  retain only implementations for which every fork and aggregate generated/direct ratio is
  `<= 1.15x`.
- Review and finalize affected Javadocs, CPU package summaries, CPU backend guide, glossary impact,
  task evidence, master-plan status, and roadmap status in a distinct clean documentation-focused
  context after implementation.
