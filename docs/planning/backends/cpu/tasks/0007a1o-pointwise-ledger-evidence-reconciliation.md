# Task 0007A1O: Pointwise Ledger Evidence Reconciliation

## Status

Complete

## Goal

Close the final evidence-accounting gap in CPU 0007A1C without rewriting historical evidence or
weakening its acceptance criteria. Replace the temporary operation/family/form ledger with one
repository-retained, automatically validated version in which every current pointwise opcode
names compatible accepted generated/direct performance evidence. Only fixed two-word
`INITIAL_STATE` and computation-free internal views may remain structural-only.

This task is evidence-first. It changes no production algorithm, generated bytes, schema,
specialization, route, resource, lifecycle, or public contract. If the audit finds a generated
pointwise code shape without compatible `<= 1.15x` direct-clean-Java evidence, stop and plan a
separate code-shaping correction instead of relabeling the row or expanding this task.

  `STRUCTURAL_ONLY:covered-by-emitted-category`. Each replacement must name one accepted retained

## Local decisions

- The original ledger contains 48 pointwise opcode rows. Eight already name concrete performance
  categories; the other 40 use the unauthorized
  `STRUCTURAL_ONLY:covered-by-emitted-category` label. `INITIAL_STATE` is the only non-view row
  allowed to remain structural-only.
- A shared scalar or Vector loop shell is not sufficient equivalence. Formula calls, immediate and
  power realization, branches, virtual masks, result representation, and stores are part of the
  generated work and therefore part of category identity.
- The corrected ledger becomes a test resource so future opcode or evidence drift fails in the
  repository instead of surviving only in a temporary evidence directory.
- Historical evidence is never edited. The replacement carries explicit version/provenance and
  is accepted only after the original checksum and all current mappings verify.
- Implementation audit context `01a032f1-a956-7ca0-9a18-4ce3f585208b` found that the retained A1A
  evidence directory is empty and therefore cannot support category reuse. Even after granting
  the three verifiable A1N pointwise categories, seventeen distinct scalar formula/call/branch
  categories remain. The former sixteen-category ceiling was therefore unsatisfiable and is
  widened to the exact 40-row unresolved-ledger bound; equivalence and performance gates are
  unchanged.
