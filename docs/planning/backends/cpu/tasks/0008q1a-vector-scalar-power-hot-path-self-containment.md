# Task 0008Q1A: Vector Scalar-Power Hot-Path Self-Containment

## Status

Ready

## Goal

Make every currently generated FLOAT32 and FLOAT64 vector scalar-power specialization self-contained with respect to Synaptik production helpers. Emit the proved `POSITIVE_ONE`, `IDENTITY`, `SQUARE`, and `RECIPROCAL` realizations directly so each generated Class-File preserves the matching optimal clean Java specialization's semantic algorithm, vector-chunk and scalar-tail dataflow, and avoidable-overhead profile.

This is structural and performance remediation discovered while executing CPU 0008Q1. It does not require literal byte-for-byte Class-File identity or guarantee identical just-in-time compiler assembly.

## Scope

- Replace the generated vector `SCALAR_POW` calls to `CpuVectorMath` for `POSITIVE_ONE` and `RECIPROCAL` with direct typed Java Vector API bytecode. Keep `IDENTITY` as a direct value and `SQUARE` as one direct typed vector multiply, and test all four realizations under one fail-closed contract.
- Cover every currently generated vector scalar-power form for FLOAT32 and FLOAT64, including `VECTOR` and caller-parallel `PARALLEL_VECTOR` orchestration; primitive-array input/output, native-order `MemorySegment` input/output, and every currently admitted ordered mixed array/segment input/output carrier pair; arbitrary legal ranges; complete vector chunks; and scalar tails.
- Cover standalone scalar-power occurrences and representative legal fused pointwise occurrences whenever surrounding instructions change local/dataflow shape. Derive the finite form inventory from current lowering, preparation, specialization, and generation rather than only the first failing CPU 0008Q1 fixture.
- Preserve exact represented exponent bits and `PowerRealization` identity. `DIRECT` remains vector-ineligible and uses the safe scalar or caller-parallel scalar fallback; no scalarization inside a vector body, lane-wise `Math.pow`/`StrictMath.pow`, approximation, or new realization is allowed.
- Advance the current-only generator compatibility schema exactly once after generated bytes change. Old artifacts are safe misses; do not add a migration reader or weaken specialization identity.
- Add semantic tests against independent typed optimal clean Java specializations for all affected realizations, types, carriers, ranges, vector chunks, and tails, including NaN classification, infinities, signed zero, subnormals, overflow, and underflow where applicable.
- Add automated Class-File/decompilation tests for direct descriptors, carrier access, vector loop and scalar-tail dataflow, exact allowed JDK calls, and absence of Synaptik-owned hot-path calls, allocation, boxing, reflection, method handles, dynamic calls, maps, string dispatch, generic carrier branches, and avoidable virtual/interface dispatch.
- Produce proportionate generated-versus-direct performance evidence from fixed equivalent Java 26 specializations. Use a source-derived finite matrix covering both lane types, all four realizations, each distinct carrier-access code shape, vector chunks and tails, and both orchestration modes; project a timed row only when Class-File inspection proves the omitted dimension does not change the relevant hot body.
- Review and finalize affected Javadocs, package summaries, the CPU backend guide, glossary impact, and planning evidence in a separate clean documentation-focused context after implementation.
