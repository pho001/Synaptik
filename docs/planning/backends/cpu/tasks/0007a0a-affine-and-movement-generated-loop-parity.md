# Task 0007A0A: Affine and Movement Generated-Loop Parity

## Status

Complete

## Goal

Establish direct-loop performance parity for the remaining generated families that already embed
typed work in their generated class: affine boundary copies and non-affine [represented-bit](../../../../glossary.md#storage-mapping-contiguity-and-injectivity) data
movement. Optimize only cold-proved dense [heap](../../../../glossary.md#term-heap)-array forms while preserving the universal
[shape](../../../../glossary.md#shape)-polymorphic `long start, long end` entry contract, every current [carrier](../../../../glossary.md#term-storage-carrier)/[layout](../../../../glossary.md#layout) form, and the
completed semantics of [CPU](../../../../glossary.md#term-cpu) 0006, 0006A, 0006A1, and 0006B.

This is the immediate first [slice](../../../../glossary.md#slice) of the post-0007A0 corrective sequence. It shares one correction
boundary because `CpuAffineCopyEmitter` and `CpuDataMovementEmitter` already emit typed carrier
loads/stores and primitive loops; both still retain avoidable long logical/address state and [array
index](../../../../glossary.md#axis-rank-scalar-vector-and-matrix) conversion in cold-proved dense heap-array cases. It does not include any bridge-only family.

### Cold-proved dense [heap](../../../../glossary.md#term-heap)-array forms

- Reuse [CPU](../../../../glossary.md#term-cpu) 0007A0's typed `DENSE_HEAP_ARRAY_INT` proof category when its existing facts are
  sufficient. Extend typed CPU-private specialization only if affine/movement compatibility needs
  an additional byte-changing structural distinction.<span data-glossary-navigation="true"> ([specialization glossary](../../../../glossary.md#term-specialization))</span>
- Keep generated entry [parameters](../../../../glossary.md#term-parameter) [shape](../../../../glossary.md#shape)-polymorphic and long-typed. Narrow `start`, `end`, initial
  addresses, and other proved array-index facts once before the hot loop. A failed proof selects
  the existing correct general-long form; it never rejects a supported occurrence.<span data-glossary-navigation="true"> ([occurrence glossary](../../../../glossary.md#term-occurrence))</span>
- For dense affine copies, emit integer logical/address locals and direct primitive-array loads and
  stores without per-element long multiply, long-to-int conversion, or geometry-table address-pair
  decoding when the cold proof makes the source and result progressions affine and unit-stride.<span data-glossary-navigation="true"> ([element glossary](../../../../glossary.md#term-element); [stride glossary](../../../../glossary.md#term-stride))</span>
- Preserve the existing address-pair/general form for non-unit, arbitrary-layout, segment, mixed,
  or otherwise unproved affine copies.<span data-glossary-navigation="true"> ([layout glossary](../../../../glossary.md#layout))</span>
- For each current movement family ([`PAD`](../../../../glossary.md#padding), `TILE`, `CONCAT`, `STACK`, `UNFOLD_AXIS`, `UNFOLD2D`,
  and `SLICE_UPDATE`), specialize dense heap-array output traversal to integer logical/address
  state when cold facts prove it safe. Hoist invariant geometry loads and family choices outside
  the element loop where the emitted structural form makes them invariant.<span data-glossary-navigation="true"> ([invariant glossary](../../../../glossary.md#term-invariant))</span>
- Preserve the family-specific generated mapping. Do not replace canonical mapping with a bulk
  copy, vector route, or different traversal unless represented-bit semantics, arbitrary legal
  ranges, and exact output ownership remain identical.<span data-glossary-navigation="true"> ([canonical glossary](../../../../glossary.md#term-canonical-form); [vector glossary](../../../../glossary.md#term-vector); [represented-bit glossary](../../../../glossary.md#storage-mapping-contiguity-and-injectivity); [ownership glossary](../../../../glossary.md#term-ownership-meanings))</span>
- Keep typed `long` address/geometry fallbacks for [`MemorySegment`](../../../../glossary.md#term-memorysegment), mixed carriers, arbitrary
  layouts, non-unit/zero strides, large ranges, and every form not proved int-safe.
