# Task 0007A0: Generated Hot-Path Parity Correction

## Reader context

“Generated” was not sufficient evidence of a fast hot loop. The local audit compared generated
scalar/vector pointwise, scan, and aggregate bodies with equivalent direct Java loops, exposing
bridge calls and avoidable long-address work in dense heap-array cases. The correction moved
typed family work into emitted bytecode and narrowed address state only where a cold proof made
integer indexing safe.

The universal entry still accepted long range bounds; segments, mixed carriers, and unproved
layouts retained their general addressing. This was a realization correction, not new Tensor
semantics or permission for Runtime to choose another route. The recorded generated/direct
timing ratios qualify the original machine and fixed cases only. Current code-generation
ownership explains the distinction between an emitted loop and a generic interpreter bridge.

Current reading alongside this historical record:

- [CPU generated-code ownership](../../../../explanation/packages/cpu.md#iogithubpho001synaptikbackendcpuinternalcodegenemit)
  — separates generation-time emitters, emitted typed work, and JVM compilation.
- [CPU portable route plans](../../../../explanation/packages/cpu.md#iogithubpho001synaptikbackendcpuinternalrouteportable)
  — separates compute form, range orchestration, and invocation-private carriers.

## Status

Complete

## Goal

Correct every performance defect measured by the completed local audit under
`/tmp/synaptik-bytecode-benchmark` before adding another [CPU](../../../../glossary.md#term-cpu) semantic family. For the audited
large dense [heap](../../../../glossary.md#term-heap)-array cases, generated [scalar](../../../../glossary.md#term-scalar) [pointwise](../../../../glossary.md#term-pointwise), generated [Vector API](../../../../glossary.md#term-vector-api) pointwise,
generated [cumulative scan](../../../../glossary.md#cumulative-scan), and generated ordinary aggregate execution must reach measurable
near-parity with equivalent direct Java loops while preserving all current semantics and general
fallbacks.

This is one cohesive generated-hot-path correction. Pointwise loop shape, [scan](../../../../glossary.md#term-cumulative-scan)/aggregate body
generation, typed [carrier](../../../../glossary.md#term-storage-carrier) access, and generated-[artifact](../../../../glossary.md#term-artifact) compatibility meet at the same
`CpuClassFileKernelGenerator` and `CpuKernelSpecialization` boundary. Splitting them would either
leave known bridge-only hot paths in a newly versioned [schema](../../../../glossary.md#term-schema) or permit compatibility reuse across
materially different generated bytes.

The correction supersedes only the former performance implementation assumptions recorded by
completed CPU 0005A/0005B/0005C/0005I/0007/0007A. Their semantic capabilities, tests, completion
status, and historical evidence remain valid and unchanged.

  31.91x for generated FLOAT64 full MIN, and 5.45x for generated FLOAT32 CUM_SUM.<span data-glossary-navigation="true"> ([fork glossary](../../../../glossary.md#term-fork-meanings); [bytecode glossary](../../../../glossary.md#term-bytecode); [element glossary](../../../../glossary.md#term-element); [scalar glossary](../../../../glossary.md#term-scalar); [FLOAT64 glossary](../../../../glossary.md#term-float64); [Vector API glossary](../../../../glossary.md#term-vector-api); [FLOAT32 glossary](../../../../glossary.md#term-float32))</span>
- Preserve equivalent direct Java loops as the comparison baseline. Generated-class creation,
  definition, cold carrier/geometry binding, allocation, initialization, verification, and output
  observation remain outside the timed region.<span data-glossary-navigation="true"> ([carrier glossary](../../../../glossary.md#term-storage-carrier); [binding glossary](../../../../glossary.md#term-binding))</span>

  mutation, hidden global tuning state, or a relaxed acceptance threshold chosen to preserve the
  current implementation.<span data-glossary-navigation="true"> ([runtime glossary](../../../../glossary.md#term-runtime))</span>

### Dense [heap](../../../../glossary.md#term-heap)-array [pointwise](../../../../glossary.md#term-pointwise) loop form

- When cold preparation and [binding](../../../../glossary.md#term-binding) prove that one dense heap-array pointwise invocation's
  `start`, `end`, initial addresses, final addresses, and every vector/scalar array access fit the
  Java array-index domain, emit a canonical <span data-glossary-navigation="true"> ([vector glossary](../../../../glossary.md#term-vector); [canonical glossary](../../../../glossary.md#term-canonical-form))</span>`int` index/address loop shape for every participating
  dense heap-array boundary.
- Keep the public/internal generated entry's [shape](../../../../glossary.md#shape)-polymorphic primitive `long start, long end`
  contract. Perform any required checked narrowing once before the generated hot loop; do not
  bake compatible concrete extents, addresses, or element counts into class identity unless the
  emitted bytes actually depend on a structural proof category.<span data-glossary-navigation="true"> ([narrowing glossary](../../../../glossary.md#term-narrowing); [identity glossary](../../../../glossary.md#term-identity-meanings))</span>
- Retain the existing checked `long` address/state forms for [`MemorySegment`](../../../../glossary.md#term-memorysegment), mixed carriers,
  non-dense access regimes, ranges not proved int-safe, and every other general case. An
  optimization proof failure selects the correct general form; it never rejects an otherwise
  supported occurrence.<span data-glossary-navigation="true"> ([occurrence glossary](../../../../glossary.md#term-occurrence))</span>
- Emit dense [scalar](../../../../glossary.md#term-scalar) array loads/stores and loop increments without per-[element](../../../../glossary.md#term-element) `long` arithmetic
  or `l2i`. Preserve arbitrary legal `start`/`end` subranges, scalar and zero-element behavior,
  all currently supported pointwise data types/opcodes, fusion lengths, and scalar/parallel
  orchestration.<span data-glossary-navigation="true"> ([fusion glossary](../../../../glossary.md#term-fusion))</span>

### Dense [heap](../../../../glossary.md#term-heap)-array [Vector API](../../../../glossary.md#term-vector-api) loop form

- For the same proved dense heap-array regime, compute exactly one [scalar](../../../../glossary.md#term-scalar) `int` vector bound before
  the vector loop, run complete preferred-species vectors to that bound, and execute one scalar
  tail from the vector bound to <span data-glossary-navigation="true"> ([vector glossary](../../../../glossary.md#term-vector); [run glossary](../../../../glossary.md#term-run); [scalar tail glossary](../../../../glossary.md#term-scalar-tail))</span>`end`.
- Do not recompute `end - index`, reload the preferred species for each input, or maintain
  redundant long logical/address availability state on every vector iteration when structural
  specialization has made those facts constant or equivalent.<span data-glossary-navigation="true"> ([specialization glossary](../../../../glossary.md#term-specialization); [constant glossary](../../../../glossary.md#term-constant))</span>
- Preserve exact existing vector eligibility, typed species, operation formulas, scalar fallback,
  arbitrary subranges, scalar tails, and parallel-vector range ownership. The correction does not
  broaden vector capability or change route-selection policy merely because one benchmark is
  faster.<span data-glossary-navigation="true"> ([operation glossary](../../../../glossary.md#operation); [ownership glossary](../../../../glossary.md#term-ownership-meanings))</span>
- Retain the existing general vector state machines for supported non-dense contiguous-run forms
  and <span data-glossary-navigation="true"> ([contiguous glossary](../../../../glossary.md#term-contiguous))</span>[`MemorySegment`](../../../../glossary.md#term-memorysegment) carriers unless an equally proved simplification applies without weakening
  semantics or bounds safety.
