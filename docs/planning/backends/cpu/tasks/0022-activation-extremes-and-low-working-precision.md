# [CPU](../../../../glossary.md#term-cpu) 0022 — Correct [activation](../../../../glossary.md#term-activation) extremes and low working [precision](../../../../glossary.md#term-precision)

## Reader context — historical integration boundary

An activation formula has represented intermediate arithmetic sites as well as a final stored type.
CPU's scalar/vector emitters must respect those sites: BFLOAT16/FLOAT16 storage can require FLOAT32
working arithmetic rather than one entire DOUBLE expression followed by a final narrowing. Large
finite ERF inputs also need safe evaluation before an overflowing polynomial creates an invalid
result. These are numerical/generated-code repairs, not new operation support or permission to relax
Model semantics. The historical identity bump below identifies changed generated bytes; the retained
vector timing gap is not evidence that numerical correctness was incomplete.

Current reading: [Unary numerical realization](../../../../backend-guide/cpu-backend.md#unary-numerical-closure).
