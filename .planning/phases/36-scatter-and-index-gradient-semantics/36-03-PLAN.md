# Plan 36-03: Gradient Parity And Duplicate-Index Gates

**Phase:** 36 Scatter And Index Gradient Semantics
**Requirements:** METALSCATTER-01, METALSCATTER-02, METALSCATTER-03
**Status:** Planned
**Wave:** 3

## Objective

Prove that supported scatter/index-gradient behavior matches CPU forward and backward semantics, especially with duplicate indices.

## Tasks

1. Add deterministic duplicate-index fixtures for `SCATTER_ADD`.
2. Add `gather` backward fixtures that produce repeated destination updates through `GATHER_GRAD`.
3. Add `takeAlongAxis` backward fixtures that produce repeated destination updates through `TAKE_ALONG_AXIS_GRAD`.
4. Cover out-of-range and unproven-index rejection in both forward scatter and gradient contexts.
5. Add prepared-execution tests that supported index-gradient regions preserve Metal ownership across adjacent supported producers/consumers.

## Acceptance Criteria

- Duplicate-index CPU parity is covered for all supported Phase 36 operations.
- Unsupported duplicate/bounds variants remain explicit and stable.
- Training/backward flows do not silently materialize through CPU when the operation is marked supported.

## Verification

```bash
./gradlew test --tests ScatterAddExecutionTest --tests GatherExecutionTest --tests TakeAlongAxisExecutionTest
./gradlew test --tests PreparedExecutionBuildTest --tests backend.metal.lowering.MetalRegionLowererTest

```

## Threat Model

- **Threat:** Forward scatter works but gradients still exit to CPU.
  **Mitigation:** Backward-specific fixtures and prepared-execution residency checks are required before closing the requirement.
