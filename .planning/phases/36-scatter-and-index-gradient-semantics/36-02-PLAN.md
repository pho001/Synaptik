# Plan 36-02: Native Or Stable-Rejection Scatter Execution

**Phase:** 36 Scatter And Index Gradient Semantics
**Requirements:** METALSCATTER-01, METALSCATTER-03
**Status:** Planned
**Wave:** 2

## Objective

Implement the narrowest safe Metal path for Phase 36 index-write operations, or preserve explicit stable rejection when native duplicate accumulation parity cannot be proven.

## Tasks

1. Evaluate `SCATTER_ADD`, `GATHER_GRAD`, and `TAKE_ALONG_AXIS_GRAD` independently against the Phase 36 semantic contract.
2. If a native/lowered path is safe, add shared accelerator DAG node types and lowerer mappings for the supported operation subset.
3. Add Metal planner legality checks for:
   - dense `FLOAT32` value/source/output,
   - dense static `INT32` indices,
   - proven in-bounds indices,
   - legal rank/axis/shape contracts,
   - duplicate accumulation semantics.
4. Add native shim execution or a backend-owned custom Metal route only for operations whose duplicate accumulation behavior matches the accepted contract.
5. Keep CUDA rows and unsupported Metal variants capability-gated with stable details.

## Acceptance Criteria

- Supported paths execute through Metal buffer binding with CPU parity.
- Unsupported paths reject before execution with operation-specific reason details.
- No CPU fallback is hidden behind a supported matrix row.

## Threat Model

- **Threat:** Duplicate indices produce last-writer-wins or nondeterministic accumulation.
  **Mitigation:** Do not mark the operation supported unless duplicate-index parity tests pass against the declared tolerance.
- **Threat:** Static index bounds are skipped.
  **Mitigation:** Reuse Phase 32 static in-bounds proof rules and reject unproven indices.
