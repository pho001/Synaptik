# Plan 36-01: Scatter/Index-Gradient Semantics Contract

**Phase:** 36 Scatter And Index Gradient Semantics
**Requirements:** METALSCATTER-01, METALSCATTER-02
**Status:** Planned
**Wave:** 1

## Objective

Lock the semantic and planner contract for `SCATTER_ADD`, `GATHER_GRAD`, and `TAKE_ALONG_AXIS_GRAD` before any Metal support claim.

## Tasks

1. Add or expand semantics contracts in `GpuTargetSemanticsContract` for duplicate-index accumulation, bounds behavior, dtype scope, and layout scope.
2. Update `GpuLoweringCoverageMatrix` notes so the three operations clearly distinguish:
   - unsupported because duplicate accumulation is unproven,
   - unsupported because bounds are unproven,
   - supported only when native parity evidence exists.
3. Add Metal and CUDA planner tests proving current unsupported paths reject with stable `UNSUPPORTED_DUPLICATE_INDEX` or `CAPABILITY_MISSING` details.
4. Add CPU parity fixtures for duplicate/repeated index accumulation as the source of truth.
5. Document the Phase 36 contract in `docs/gpu-lowering-coverage.md` and `docs/metal-backend.md`.

## Acceptance Criteria

- Every Phase 36 target operation has an explicit matrix row and semantics contract.
- Current unsupported behavior is visible and reason-coded; no generic unlisted operation fallback remains.
- CPU duplicate-index behavior is tested before native GPU admission.

## Threat Model

- **Threat:** A future native implementation is admitted before duplicate-index semantics are locked.
  **Mitigation:** Matrix, planner, docs, and CPU parity fixtures must all fail unsupported or unproven claims.
