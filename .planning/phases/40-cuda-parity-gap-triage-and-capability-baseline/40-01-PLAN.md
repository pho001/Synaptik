# Plan 40-01: CUDA Parity Matrix And Report Vocabulary

**Phase:** 40 CUDA Parity Gap Triage And Capability Baseline
**Requirements:** CUDAPARITY-01
**Status:** Planned
**Wave:** 1

## Objective

Create a code-level CUDA-vs-Metal parity report derived from `GpuLoweringCoverageMatrix` so v1.6 implementation work starts from auditable support, fallback, and blocker truth.

<action>
Add `GpuBackendParityRow` under `src/main/java/backend/accelerator/lowering/` with these fields: `Operation.OpType opType`, `GpuLoweringOperationFamily family`, `GpuLoweringCoverageStatus metalStatus`, `GpuLoweringUnsupportedReason metalReason`, `String metalNote`, `GpuLoweringCoverageStatus cudaStatus`, `GpuLoweringUnsupportedReason cudaReason`, `String cudaNote`, `boolean metalSupported`, `boolean cudaSupported`, `boolean parityGap`, and `String requiredEvidence`.

The `requiredEvidence` value must be deterministic:
- `NONE` when both Metal and CUDA are supported or both are unsupported for the same reason.
- `CUDA_NATIVE_EXECUTION_REQUIRED` when Metal is supported and CUDA is fallback or unsupported because of `CAPABILITY_MISSING` or `DAG_PRIMITIVE_UNSUPPORTED`.
- `CUDA_DTYPE_OR_LAYOUT_CONTRACT_REQUIRED` when CUDA reason is `UNSUPPORTED_DTYPE` or `UNSUPPORTED_LAYOUT`.
- `CUDA_INDEX_SEMANTICS_REQUIRED` when CUDA reason is `UNSUPPORTED_INDEX_SEMANTICS`, `UNSUPPORTED_DUPLICATE_INDEX`, or `UNSUPPORTED_BOUNDS_CHECK`.
- `CUDA_EXPLICIT_REJECTION_OK` for rows that are intentionally unsupported in both backends.
</action>

- `src/main/java/backend/accelerator/lowering/GpuBackendParityRow.java` exists.
- The file contains the exact strings `CUDA_NATIVE_EXECUTION_REQUIRED`, `CUDA_DTYPE_OR_LAYOUT_CONTRACT_REQUIRED`, `CUDA_INDEX_SEMANTICS_REQUIRED`, and `CUDA_EXPLICIT_REJECTION_OK`.
- The record exposes `parityGap` and `requiredEvidence`.
</acceptance_criteria>
</task>

## Threat Model

- **T40-01:** A generated parity row could promote CUDA fallback to support because Metal supports the same operation.
  **Mitigation:** Derive support strictly from CUDA row status and add tests proving `CAPABILITY_MISSING` is not support.
