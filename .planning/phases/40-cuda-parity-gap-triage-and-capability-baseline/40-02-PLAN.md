# Plan 40-02: CUDA Capability And ABI Probe Hardening

**Phase:** 40 CUDA Parity Gap Triage And Capability Baseline
**Requirements:** CUDAPARITY-02
**Status:** Planned
**Wave:** 2
**Depends on:** 40-01

## Objective

Make CUDA native capability evidence layered enough to distinguish native library, runtime, graph ABI, buffer ABI, layout ABI, dtype role, DAG primitive, vendor-library route, hardware, and toolchain state without treating capability skips as support.

Extend `CudaBridgeCapabilities` with a `CudaCapabilityReport report()` method or field. The report must map existing booleans and `CudaBridgeCapabilityCode` to dimension entries:
- `NATIVE_LIBRARY` is `AVAILABLE` only when `nativeLibraryAvailable` is true.
- `CUDA_RUNTIME` and `HARDWARE_DEVICE` are `AVAILABLE` only when `cudaRuntimeAvailable` is true.
- `CONTEXT` is `AVAILABLE` only when `contextAvailable` is true.
- `GRAPH_EXECUTION_ABI` is `AVAILABLE` only when `graphExecutionAvailable` is true.
- `BUFFER_BINDING_ABI` is `AVAILABLE` only when `bufferExecutionSupported` is true.
- `LAYOUT_ABI_V2` is `AVAILABLE` only when `layoutAbiV2Supported` is true; otherwise use `VERSION_MISMATCH` when `layoutAbiV2Version > 0`.
- `DTYPE_ROLE` must report `AVAILABLE` for `FLOAT32 compute/output` and `UNAVAILABLE` for `BFLOAT16 compute/output`, `BOOL output`, and `INT32 compute/output`.
- `DAG_PRIMITIVE` must summarize current CUDA supported and unsupported families from `GpuBackendParityReport`.
- `VENDOR_LIBRARY_ROUTE` must be `NOT_INTEGRATED` with detail `cuBLAS/cuDNN routing is not integrated in the CUDA graph bridge`.
- `TOOLCHAIN` must be `UNKNOWN` unless the bridge can prove a native shim is loaded.
</action>

## Threat Model

- **T40-02:** Capability reports could imply cuBLAS/cuDNN or dtype support that the bridge does not implement.
  **Mitigation:** Hard-code unsupported role evidence until native routes exist and test the exact unsupported details.
