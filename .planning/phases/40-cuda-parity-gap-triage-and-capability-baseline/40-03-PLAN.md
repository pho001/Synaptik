# Plan 40-03: CUDA Hot-Path Target Policy And Blocker Classification

**Phase:** 40 CUDA Parity Gap Triage And Capability Baseline
**Requirements:** CUDAPARITY-03
**Status:** Planned
**Wave:** 3
**Depends on:** 40-01, 40-02

## Objective

Classify CUDA hot-path exits as implementation blockers, accepted capability gaps, future scope, or native-evidence-required rows so v1.6 closes the highest-value CPU exits first.

## Success Criteria

- CUDA hot-path target report shows blocker classes instead of raw fallback reasons only.
- v1.6 priority targets are explicit and auditable.
- Accepted capability gaps are not counted as hidden success.

## Threat Model

- **T40-03:** Hot-path reports could hide a CPU exit under "accepted gap" and make v1.6 look better than it is.
  **Mitigation:** Emit blocker class and detail in both text and JSON reports and keep accepted gaps separate from supported paths.
