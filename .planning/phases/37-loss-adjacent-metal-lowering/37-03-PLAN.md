# Plan 37-03: Loss Backward And Training Boundary Gates

**Phase:** 37 Loss-Adjacent Metal Lowering
**Requirements:** METALLOSS-02, METALLOSS-03
**Status:** Complete
**Wave:** 3

## Objective

Integrate loss-adjacent support with training-mode prepared execution while keeping unsupported backward/index-gradient exits visible.

## Tasks

1. Audit backward graph nodes generated by dense and index-target loss flows.
2. Add prepared-execution tests for supported forward loss regions in `FORWARD_BACKWARD` mode.
3. Verify legal forward loss-adjacent producers stay Metal-owned until a real unsupported backward boundary.
4. Ensure unsupported loss gradients report stable blockers instead of hidden CPU materialization:
   - `CROSS_ENTROPY_LOSS_INDICES_GRAD`,
   - Phase 36 scatter/index-gradient blockers,
   - ignore-index/class-weight gradient variants.
5. Add trace assertions distinguishing expected gradient publication from avoidable internal CPU materialization.

## Acceptance Criteria

- Training traces show which loss-adjacent subregions stay on Metal and where they exit.
- Unsupported backward variants remain explicit CPU prepared steps or stable rejected candidates.
- No test treats final gradient publication as a hidden internal fallback.

## Threat Model

- **Threat:** A training workload looks faster because the unsupported loss gradient is silently replayed on CPU.
  **Mitigation:** Prepared-execution and trace tests must assert visible backend ownership, CPU step, and rejection reason boundaries.
