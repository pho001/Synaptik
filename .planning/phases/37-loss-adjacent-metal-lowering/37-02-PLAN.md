# Plan 37-02: Dense And Index-Target Loss Admission

**Phase:** 37 Loss-Adjacent Metal Lowering
**Requirements:** METALLOSS-01, METALLOSS-02, METALLOSS-03
**Status:** Planned
**Wave:** 2

## Objective

Implement scoped Metal loss-adjacent admission where semantics are proven, and preserve explicit rejection for index-target variants that remain unsafe.

## Tasks

1. Add lowered DAG support for scoped dense `NLL_LOSS` / `CROSS_ENTROPY_LOSS` using existing Metal-supported primitives or a backend-owned primitive if lowering is not sufficient.
2. Add native/buffer execution parity tests for supported dense `FLOAT32` cases against CPU.
3. Evaluate `CROSS_ENTROPY_LOSS_INDICES` and `NLL_LOSS` index-target variants independently:
   - no ignore-index,
   - ignore-index,
   - class weights,
   - `MEAN`, `SUM`, and `NONE` reductions,
   - static INT32 bounds.
4. Admit only the smallest forward index-target subset whose target, bounds, and denominator semantics are proven; otherwise keep stable `UNSUPPORTED_INDEX_SEMANTICS` / `UNSUPPORTED_IGNORE_INDEX` rejection.
5. Ensure `CROSS_ENTROPY_LOSS_INDICES_GRAD` remains explicit and does not inherit forward admission while Phase 36 index-gradient blockers remain.

## Acceptance Criteria

- Supported dense loss variants execute on Metal and match CPU within declared tolerances.
- Unsupported index-target variants expose stable reason codes.
- Forward index-target support, if any, is documented as forward-only unless backward support is separately proven.

## Threat Model

- **Threat:** Ignore-index or class weights silently change the denominator or gradient scale.
  **Mitigation:** Unsupported variants must reject until CPU parity fixtures cover the exact semantic combination.
