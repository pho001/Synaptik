# Plan 39-01: Router Policy And Cost Evidence Model

**Phase:** 39 Metal Backend Router And Zero-Copy Closure
**Requirements:** METALROUTER-01, METALROUTER-03
**Status:** Complete
**Wave:** 1

## Objective

Create a prepare-time Metal route decision model that sits inside selected `GPU_METAL` regions and records why MPSGraph, custom kernel, tensor-array fallback, or CPU fallback is preferred.

## Tasks

1. Add Metal route decision records:
   - `MetalExecutionRoute` enum with at least `MPS_GRAPH`, `CUSTOM_KERNEL`, `TENSOR_ARRAY`, `CPU_FALLBACK`, and `UNAVAILABLE_REQUIRED`.
   - `MetalRouteReasonCode` enum with stable values for selected MPSGraph, custom kernel unavailable, bridge unavailable, buffer ABI unavailable, tensor-array fallback, CPU fallback, insufficient work, unsupported dtype, unsupported layout, unsupported operation family, and native-copy cost unknown.
   - `MetalRouteDecision` record containing selected route, rejected routes, reason code, detail, estimated work, estimated route cost, copy cost estimate, and native evidence flags.
2. Add a `MetalExecutionRouter` prepare-time service that consumes:
   - `MetalPartitionPlan`
   - `MetalMpsGraphBridge.capabilities()`
   - `AcceleratorBackendConfig`
   - lowered-region manifest metadata
   - static transport plan availability from `PreparedMetalExecutable`
3. Wire the router into `PreparedMetalExecutable` without changing public `Tensor` APIs.
4. Add trace attributes to Metal execution steps:
   - `metalExecutionRoute`
   - `metalRouteReasonCode`
   - `metalRouteRejectedRoutes`
   - `metalRouteEstimatedCost`
   - `metalRouteEstimatedCopyCost`
5. Add tests proving current supported Metal regions select `MPS_GRAPH` and unsupported route candidates remain visible.

## Acceptance Criteria

- `src/main/java/backend/metal/exec/MetalExecutionRoute.java` contains `MPS_GRAPH`, `CUSTOM_KERNEL`, `TENSOR_ARRAY`, `CPU_FALLBACK`, and `UNAVAILABLE_REQUIRED`.
- `src/main/java/backend/metal/exec/MetalRouteReasonCode.java` contains `CUSTOM_KERNEL_UNAVAILABLE`, `MPS_GRAPH_SELECTED`, and `NATIVE_COPY_COST_UNKNOWN`.
- `PreparedMetalExecutable` publishes `metalExecutionRoute` and `metalRouteReasonCode` attributes for every Metal step.
- A targeted test asserts an existing `BUFFER_BINDING` Metal step reports `metalExecutionRoute=MPS_GRAPH`.
- Existing buffer/tensor-array/CPU fallback reason attributes remain present.

## Threat Model

- **Threat:** The new router duplicates backend selection and changes which graph regions are selected for Metal.
  **Mitigation:** Keep router scope inside already-selected `GPU_METAL` regions and assert backend selection traces remain unchanged for existing workloads.
