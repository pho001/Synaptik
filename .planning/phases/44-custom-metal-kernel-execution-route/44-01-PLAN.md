# Plan 44-01: Custom Metal Kernel Candidate Contract

**Phase:** 44 Custom Metal Kernel Execution Route
**Requirements:** METALKERNEL-01, METALKERNEL-02, METALKERNEL-03
**Status:** Planned
**Wave:** 1

## Objective

Define the first custom Metal kernel candidate subset and make route selection truthful before adding native execution.

## Tasks

1. Add candidate metadata for the scoped first custom kernel route.
2. Restrict custom route eligibility to a dense `FLOAT32` buffer-bound candidate subset.
3. Update `MetalCustomKernelRouteAdapter` and `MetalExecutionRouter` so an available custom executable can select `CUSTOM_KERNEL` instead of always rejecting it.
4. Preserve MPSGraph selection when:
   - custom bridge is unavailable,
   - custom executable is unavailable,
   - transport path is not native buffer binding,
   - dtype/layout/candidate shape is outside scope.
5. Add route unit tests for selected and rejected custom-kernel paths.

## Acceptance Criteria

- `CUSTOM_KERNEL` can be selected only when custom executable evidence and buffer transport evidence are available.
- MPSGraph remains the default route for unsupported custom-kernel candidates.
- Route reports include rejected alternatives and reason codes.

## Threat Model

- **T44-01:** Route metadata claims custom-kernel execution while MPSGraph still executes.
  **Mitigation:** Execution and route tests must assert selected route and execution path together before support is claimed.
