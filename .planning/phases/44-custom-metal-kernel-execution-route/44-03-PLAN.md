# Plan 44-03: Route Reporting And Coverage Evidence

**Phase:** 44 Custom Metal Kernel Execution Route
**Requirements:** METALKERNEL-03
**Status:** Planned
**Wave:** 3

## Objective

Make custom Metal kernel execution visible in traces and coverage reports without conflating it with MPSGraph, tensor-array fallback, or CPU fallback.

## Tasks

1. Ensure trace metadata reports:
   - `metalExecutionRoute=CUSTOM_KERNEL`,
   - selected reason code,
   - rejected route list,
   - custom-kernel availability,
   - estimated route/copy cost.
2. Extend coverage summary/report tests to distinguish custom-kernel steps from MPSGraph steps.
3. Add regression tests proving MPSGraph-supported rows do not regress when custom route is unavailable.
4. Keep copy strategy reporting separate from custom route selection.

## Acceptance Criteria

- Reports distinguish MPSGraph and custom Metal kernel routes.
- Custom route availability does not hide tensor-array or CPU fallback.
- MPSGraph behavior remains stable when custom route is disabled.

## Verification

```bash
./gradlew test --tests CompiledGraphTraceTest --tests GpuCoverageSummaryTest --tests backend.metal.exec.MetalExecutionRouterTest
```

## Threat Model

- **T44-03:** Reports show GPU coverage but not which native route actually ran.
  **Mitigation:** Trace/report tests must assert explicit route fields and rejected route evidence.
