<objective>
Extend the GPU coverage regression gate so Phase 18/19 evidence can be enforced as a hard policy, not just rendered.
</objective>

<source_audit>
REQ GPUHARDEN-01: Covered by extending policy inputs and gate result coverage evidence.
REQ GPUHARDEN-02: Covered by stable failure semantics and tests for every hard regression class.
D-01: Gate pass/fail uses coverage/materialization evidence, not raw timing.
D-03: Gate failures cover lost region length, lowered/fused evidence loss, CPU materialization, tensor-array fallback, CPU fallback, device handoff, native binding loss, and missing summaries.
D-04: Gate policy remains deterministic and reviewable through checked-in Java policy records.
D-05: Gate evaluation consumes structured trace/report fields instead of prose-only benchmark interpretation.
D-06: Native buffer binding remains separate from tensor-array bridge execution.
D-07: Hot-path GPU proof remains trace/report based even when benchmark timing looks favorable.
</source_audit>

<threat_model>
T-20-01: A hot path could lose lowered/fused evidence while old ratio/region checks still pass. Mitigation: add explicit minimum lowered primitive, multi-op region, and fused subpattern thresholds.
T-20-02: Gate failures could collapse into generic `lost GPU coverage`. Mitigation: add stable failure strings for each Phase 20 failure mode.
</threat_model>
