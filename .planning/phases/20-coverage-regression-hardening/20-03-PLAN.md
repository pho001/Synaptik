<objective>
Make gate results and native evidence reviewable in benchmark reports so milestone audit can inspect hot-path GPU residency without rerunning local profiling.
</objective>

<source_audit>
REQ GPUHARDEN-01: Covered by rendering all gate input fields.
REQ GPUHARDEN-02: Covered by rendering gate pass/fail failures for target policies.
REQ GPUHARDEN-03: Covered by native pass/skip evidence fields and portable report tests.
D-12: Portable Java gates prove schema, failure semantics, and fallback visibility without requiring CUDA or native Metal/CUDA availability.
D-13: Native Metal and CUDA evidence remains capability-gated and skipped-by-environment evidence is explicit.
D-14: CUDA hardware absence is treated as an environment risk, not a reason to weaken portable gate contracts.
D-15: Text and JSON reports expose gate inputs and gate results so milestone audit can review whether hot paths stayed on GPU.
</source_audit>

<threat_model>
T-20-05: A report could show coverage fields but hide that the hard gate failed. Mitigation: render gate result status and failure strings.
T-20-06: Native CUDA/Metal evidence could be silently skipped. Mitigation: render explicit native evidence status and skip reason.
</threat_model>
