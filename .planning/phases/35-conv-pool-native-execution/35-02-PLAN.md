# Plan 35-02: Conv2D Forward Native/Lowered Execution

**Phase:** 35 Conv Pool Native Execution
**Requirements:** METALCONVPOOL-01, METALCONVPOOL-03
**Status:** Planned
**Wave:** 2

## Objective

Add native or lowered Metal forward execution for the first scoped Conv2D subset with CPU parity and native buffer evidence.

## Tasks

1. Add accelerator DAG representation for Conv2D forward metadata or a backend-specific routed primitive descriptor.
2. Implement Metal native execution for dense `FLOAT32` rank-4 NCHW input, OIHW weight, groups=1, dilation=1, symmetric padding, stride, and optional bias.
3. Preserve explicit rejection for unsupported groups, dilation, dtype, non-dense layout, invalid rank, and unsupported `CONV2D_GEMM` variants.
4. Add native bridge parity tests for:
   - no-bias conv,
   - bias conv,
   - stride/padding representative case,
   - unsupported grouped/dilated rejection.
5. Add prepared execution tests proving selected Metal Conv2D uses native buffer binding and matches CPU.

## Acceptance Criteria

- Legal Conv2D forward cases execute through Metal and match CPU within FLOAT32 tolerance.
- Unsupported Conv2D variants reject visibly and do not enter hidden tensor-array fallback in REQUIRE mode.
- `CONV2D_GEMM` remains separate unless explicitly implemented.

## Threat Model

- **Threat:** MPSGraph expects NHWC/HWIO while Synaptik tensors are NCHW/OIHW.
  **Mitigation:** Add explicit transpose or dimension descriptor logic and parity tests that would fail on layout inversion.
- **Threat:** Bias broadcasting differs.
  **Mitigation:** Test per-output-channel bias with asymmetric values.
