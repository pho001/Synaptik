# Plan 35-03: Max/Avg Pool Forward Native/Lowered Execution

**Phase:** 35 Conv Pool Native Execution
**Requirements:** METALCONVPOOL-02, METALCONVPOOL-03
**Status:** Planned
**Wave:** 3

## Objective

Add native or lowered Metal forward execution for selected max and average pooling variants with CPU parity and precise rejection of unsupported divisor/tie/layout cases.

## Tasks

1. Add accelerator DAG representation for max/avg pool forward metadata or backend-specific routed primitive descriptors.
2. Implement Metal native execution for dense `FLOAT32` rank-4 NCHW pooling.
3. For max pool, document and test forward value behavior; keep backward tie/argmax semantics out of support scope.
4. For avg pool, support only divisor semantics proven to match CPU (`countIncludePad` true/false as implemented), and reject the other if native behavior differs.
5. Add native bridge and prepared execution parity tests for representative kernel/stride/padding cases.
6. Keep pooling backward ops explicitly unsupported for Phase 38.

## Acceptance Criteria

- Legal max/avg pool forward cases execute through Metal and match CPU.
- Unsupported pool variants reject with stable reason codes.
- Coverage can distinguish max and avg pool native support from backward gaps.

## Threat Model

- **Threat:** Avg-pool divisor differs for padded windows.
  **Mitigation:** Gate `countIncludePad` precisely and test padded and unpadded windows.
- **Threat:** Max-pool tie handling is mistaken for backward support.
  **Mitigation:** Docs and matrix state forward support only; backward rows stay unsupported.
