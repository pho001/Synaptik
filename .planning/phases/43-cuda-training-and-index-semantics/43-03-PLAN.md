# Plan 43-03: CUDA Training Hot-Path Report Targets

**Phase:** 43 CUDA Training And Index Semantics
**Requirements:** CUDATRAIN-03
**Status:** Planned
**Wave:** 3

## Objective

Harden CUDA training hot-path target expectations so unsupported training rows pass only with visible blockers and supported rows can never hide internal CPU materialization.

## Tasks

1. Add `CUDATRAIN` requirement-family metadata to CUDA training targets and scatter/index-gradient target metadata where appropriate.
2. Verify CUDA expectations for:
   - `training_transformer_block_hot_path`
   - `training_dense_loss_small`
   - `training_reduction_chain_small`
   - `training_layer_norm_small`
   - `training_cross_entropy_small`
   - `scatter_index_gradient_small`
3. Ensure unsupported CUDA training targets require visible blocker strings such as:
   - `SCALED_DOT_PRODUCT_ATTENTION_BACKWARD`
   - `DAG_PRIMITIVE_UNSUPPORTED`
   - `UNSUPPORTED_INDEX_SEMANTICS`
   - `UNSUPPORTED_DUPLICATE_INDEX`
   - `CAPABILITY_MISSING`
4. Keep `GRADIENT_PUBLICATION` separate from hidden internal CPU materialization in coverage gate policy.
5. Add report/gate tests proving CUDA training gaps cannot pass as native coverage.

## Acceptance Criteria

- CUDA training hot-path targets are mapped to `CUDATRAIN`.
- Unsupported CUDA training rows are visible blockers, not silent shortened-region success.
- Supported CUDA training rows, if any, must satisfy native buffer and no-hidden-internal-materialization gates.

## Threat Model

- **T43-03:** CUDA training reports pass because gradient publication or CPU fallback is indistinguishable from device-owned internal training execution.
  **Mitigation:** Gate policy and tests must keep `GRADIENT_PUBLICATION`, internal CPU materialization, tensor-array replay, and CPU fallback separate.
