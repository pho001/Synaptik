# Plan 43-01: CUDA Backward Truth And Gate Policy

**Phase:** 43 CUDA Training And Index Semantics
**Requirements:** CUDATRAIN-01
**Status:** Planned
**Wave:** 1

## Objective

Make CUDA backward/training coverage truth explicit so forward CUDA support, shared matrix support, and native executable training evidence cannot be confused.

## Tasks

1. Audit CUDA rows in `GpuTargetCoverageTruth` for:
   - `SOFTMAX_GRAD`
   - `LOG_SOFTMAX_GRAD`
   - `REDUCE_MIN_GRAD`
   - `REDUCE_MAX_GRAD`
   - `MIN_GRAD`
   - `MAX_GRAD`
   - `SCALED_DOT_PRODUCT_ATTENTION_BACKWARD`
   - conv/pool backward variants
   - index gradients and scatter
   - index-target loss gradients
2. Add or adjust tests proving CUDA native-executable truth is not inferred from:
   - forward operation support,
   - matrix `SUPPORTED` rows,
   - Metal native executable rows.
3. Ensure CUDA training/backward blocker detail distinguishes:
   - `MATRIX_SUPPORTED_ONLY`
   - `CAPABILITY_MISSING`
   - `UNSUPPORTED_DUPLICATE_INDEX`
   - `UNSUPPORTED_INDEX_SEMANTICS`
4. Keep any CUDA backward promotion out of scope unless native execution and parity evidence already exists.

## Acceptance Criteria

- CUDA backward truth rows are auditable and operation-specific.
- CUDA unsupported training rows do not appear as native executable target truth.
- Tests fail if a CUDA backward row is promoted solely by matrix support or forward support.

## Threat Model

- **T43-01:** Forward CUDA support or shared DAG support accidentally implies CUDA backward native execution.
  **Mitigation:** Target truth tests must assert CUDA backward rows independently from forward rows and Metal rows.
