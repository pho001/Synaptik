# Plan 43-02: CUDA Scatter And Index-Gradient Semantics

**Phase:** 43 CUDA Training And Index Semantics
**Requirements:** CUDATRAIN-02
**Status:** Planned
**Wave:** 2

## Objective

Give CUDA `SCATTER_ADD`, `GATHER_GRAD`, and `TAKE_ALONG_AXIS_GRAD` the same semantics-first rejection discipline that Phase 41 gave forward gather/take and Phase 36 gave Metal index-write operations.

## Tasks

1. Add CUDA index-write/gradient semantic checks before generic matrix rejection.
2. Validate scoped inputs:
   - dense `FLOAT32` value/source/output tensors,
   - dense static `INT32` indices,
   - rank 1..4,
   - legal axis,
   - expected public output shape,
   - expected index/source/out-grad shapes,
   - static in-bounds index data.
3. Keep final legal candidates as `UNSUPPORTED_DUPLICATE_INDEX` unless native CUDA duplicate-index accumulation semantics are proven.
4. Add tests for:
   - valid semantic contract ending in duplicate-index blocker,
   - bad index dtype,
   - non-dense layout,
   - out-of-bounds indices,
   - illegal shape/rank/axis,
   - separation from forward `GATHER` / `TAKE_ALONG_AXIS`.

## Acceptance Criteria

- CUDA index-write and index-gradient rows no longer return only generic matrix detail for invalid contracts.
- Duplicate-index accumulation remains a visible blocker for legal candidates.
- No CUDA scatter/index-gradient native support is claimed without execution evidence.
