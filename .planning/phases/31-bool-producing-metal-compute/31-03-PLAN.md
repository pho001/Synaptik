# Plan 31-03: Mask Chain Residency And WHERE Consumer Gates

**Phase:** 31 BOOL-Producing Metal Compute
**Requirements:** METALBOOL-02
**Status:** Planned
**Wave:** 3

## Objective

Prove that a Metal-produced BOOL mask can feed legal GPU consumers, especially `WHERE`, without materializing to CPU between supported region steps.

## Tasks

1. Update Metal region legality and lowering so `compare -> WHERE` can be selected as one Metal-owned lowered region.
2. Ensure `ExecutionState` and `MetalBufferBinding` can carry BOOL intermediate outputs as device-current inputs to later Metal steps.
3. Add prepared-execution tests for `GT/GE/... -> WHERE -> elementwise` paths with no `CPU_CONSUMER` materialization between compare and `WHERE`.
4. Update `bool_compare_where_small` coverage expectations from visible blocker to supported Metal native evidence when the implementation is complete.
5. Add regression gates that fail hidden tensor-array fallback, CPU fallback, CPU materialization, or missing BOOL dtype residency evidence.
6. Keep masked SDPA admission out of scope while documenting that Phase 34 consumes this mask-residency foundation.

## Acceptance Criteria

- `bool_compare_where_small` can report Metal native path evidence for supported compare-to-where flows.
- Coverage reports expose BOOL dtype residency and native buffer evidence.
- Hidden CPU exits between BOOL producer and `WHERE` fail tests.
- Unsupported consumers still reject with stable reason codes.

## Threat Model

- **Threat:** Compare executes on Metal but mask chain still exits to CPU.
  **Mitigation:** Gate on materialization counts, tensor-array step count, and dtype residency evidence.
- **Threat:** Mask support accidentally admits masked SDPA semantics.
  **Mitigation:** Keep direct masked SDPA rejection tests until Phase 34.
