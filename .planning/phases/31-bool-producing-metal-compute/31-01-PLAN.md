# Plan 31-01: BOOL Output ABI And Compare Primitive Contract

**Phase:** 31 BOOL-Producing Metal Compute
**Requirements:** METALBOOL-01, METALBOOL-02
**Status:** Complete
**Wave:** 1

## Objective

Add the Java/native contract needed for Metal to produce device-resident BOOL outputs without yet claiming every BOOL operation family.

## Tasks

1. Extend Metal dtype capability truth for native BOOL output/compute roles only where an operation-specific decision supports it.
2. Add accelerator DAG node types and ABI codes for `GT`, `GE`, `LT`, `LE`, `EQ`, and `NE`.
3. Update `AcceleratorSubgraphLowerer` to lower supported compare ops to BOOL-output DAG nodes with dtype metadata.
4. Update Metal planner legality so compare ops can become legal only for supported numeric input dtypes, dense layouts, and BOOL output.
5. Keep logical ops and BOOL reductions rejected until later plans.
6. Add tests that compare rows are contract-ready for Metal and still capability-gated or rejected for CUDA.

## Acceptance Criteria

- Compare ops have explicit accelerator DAG node types and stable ABI codes.
- Metal capability checks distinguish BOOL storage/predicate input from BOOL-producing compute/output.
- Unsupported BOOL operation families still reject visibly.
- CUDA does not inherit Metal BOOL support.

## Threat Model

- **Threat:** BOOL residency is confused with BOOL native compute.
  **Mitigation:** Require operation-specific BOOL output decisions and tests for unsupported roles.
- **Threat:** ABI codes collide with existing native DAG values.
  **Mitigation:** Add new enum values after existing codes and verify descriptor emission.
