# Plan 33-01: Layout Router Contract And Reason Vocabulary

**Phase:** 33 GPU Layout Router And Strided Materialization
**Requirements:** METALLAYOUT-01, METALLAYOUT-02
**Status:** Planned
**Wave:** 1

## Objective

Define a backend-neutral layout router contract that distinguishes metadata-only views, dense GPU materialization, broadcast GPU materialization, selected strided-native compute, and explicit unsupported cases with stable reason codes.

## Tasks

1. Extend `AcceleratorLayoutTransformKind` or add a small router result type so layout repair decisions can name:
   - `METADATA_ONLY_VIEW`
   - `DENSE_GPU_MATERIALIZATION`
   - `BROADCAST_GPU_MATERIALIZATION`
   - `STRIDED_NATIVE_COMPUTE`
   - `UNSUPPORTED`
2. Add stable `AcceleratorBufferReasonCode` values for broadcast materialization availability/rejection and strided-native availability/rejection.
3. Update `AcceleratorLayoutTransformPlanner` decision rules to classify:
   - existing metadata-only view ops without behavior regression,
   - `CONTIGUOUS` and non-dense `RESHAPE` as dense materialization,
   - zero-stride broadcast repair as a distinct route when the target is dense and backend policy allows it,
   - direct strided compute only when explicitly requested and operation/backend support is proven.
4. Add tests for dense, metadata-only, broadcast, strided, backend mismatch, missing source binding, and unsupported layout decisions.
5. Keep CUDA decisions capability-gated/unsupported unless existing CUDA materializer support already proves the route.

## Acceptance Criteria

- Router decisions expose machine-checkable route kind and reason code instead of only free-form layout text.
- Broadcast zero-stride and arbitrary strided cases are not conflated.
- Existing Phase 10/32 layout behavior remains compatible.
- Unsupported routes carry enough detail for REQUIRE-mode failures and coverage reports.

## Threat Model

- **Threat:** Router labels overclaim support before native execution exists.
  **Mitigation:** Keep availability reasons separate from backend materializer capability and preserve unsupported decisions until Wave 2 proves execution.
- **Threat:** CUDA inherits Metal-specific support by shared enum expansion.
  **Mitigation:** Backend id and capability checks remain part of each decision.
