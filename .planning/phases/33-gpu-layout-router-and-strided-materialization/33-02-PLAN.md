# Plan 33-02: Metal GPU-Side Materialization Primitives

**Phase:** 33 GPU Layout Router And Strided Materialization
**Requirements:** METALLAYOUT-01, METALLAYOUT-02
**Status:** Completed
**Wave:** 2

## Objective

Implement or explicitly gate Metal GPU-side layout materialization primitives so legal layout repair can produce dense Metal bindings without CPU materialization.

## Tasks

1. Audit the existing native `synaptik_layout_contiguous_f32` path and Java `MetalDeviceLayoutMaterializer` for rank, dtype, storage-offset, zero-stride, and bounds assumptions.
2. Extend Metal materialization support for scoped broadcast zero-stride repair when the target layout is dense and physical span validation proves safe.
3. Decide and implement one of:
   - widen native layout materialization to BF16/BOOL where native parity is straightforward, or
   - keep BF16/BOOL/INT32 materialization rejected with stable dtype-specific layout reasons.
4. Ensure materialized dense bindings are attached with correct node id, dtype, shape, strides, access mode, storage residency, and resource ownership.
5. Add native parity tests for supported paths:
   - permuted/strided FLOAT32 -> dense,
   - non-zero-offset view -> dense if admitted,
   - broadcast zero-stride -> dense if admitted,
   - explicit dtype/rank/layout rejection cases.

## Acceptance Criteria

- Supported Metal layout repairs run through device buffer materialization, not CPU tensor arrays.
- Broadcast repair either has CPU parity and native execution or a stable unsupported reason.
- Dtype limitations are explicit and do not imply generic dtype compute.
- Native symbol/capability absence remains a visible fallback reason.

## Threat Model

- **Threat:** Zero-stride broadcast accepts invalid source spans.
  **Mitigation:** Validate storage offset, logical shape, strides, and physical byte span before native dispatch; add negative tests.
- **Threat:** Materialized binding aliases a source handle incorrectly.
  **Mitigation:** Allocate a distinct destination buffer for dense materialization and register it as a run resource.
