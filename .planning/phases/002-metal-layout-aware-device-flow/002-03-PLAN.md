<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Native Metal execution -> traced runtime state | Native success must be distinguishable from tensor-array fallback or CPU fallback. |
| Device-owned graph output -> user-visible tensor | Output publication requires correct CPU materialization and trace reason. |
| Device-owned gradient -> source tensor gradient | Gradient publication must not expose stale Java arrays. |
| Test/native environment -> repository state | Native and verification runs can generate local artifacts that must not become committed phase output. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-002-03-01 | Repudiation | `MetalBufferTraceSmokeTest` | mitigate | Assert execution path, storage residency, materialization reasons, and fallback reason codes in trace metadata. |
| T-002-03-02 | Tampering | `MetalLayoutAwareDeviceFlowTest` CPU parity | mitigate | Compare Metal outputs and gradients against CPU baseline for representative forward and forward-backward graphs. |
| T-002-03-03 | Spoofing | Native success diagnostics | mitigate | Require `metalExecutionPath=BUFFER_BINDING` and `metalNativeToJavaCopyNs=0L` for native buffer success assertions. |
| T-002-03-04 | Information Disclosure | Local profile artifacts | accept | No secrets involved, but plan acceptance forbids staging local benchmark/calibration outputs. |
| T-002-03-05 | Denial of Service | Verification command selection | mitigate | Use targeted Gradle filters before `metalTest` to avoid default debug benchmark suite delays. |
</threat_model>
