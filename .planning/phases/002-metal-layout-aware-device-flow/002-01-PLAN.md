<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Runtime tensor layout -> Metal preflight | Untrusted runtime shape/stride/offset facts decide whether native Metal buffers may be used. |
| Existing device binding -> native execution | A stale or incompatible binding could be treated as current input without CPU validation. |
| Optional buffer path -> fallback trace | Fallback must be explicit so unsupported layouts do not look like native success. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-002-01-01 | Tampering | `MetalLayoutPolicy` | mitigate | Encode exact accepted/rejected layout classes and require reason text with layout class, shape, strides, and storage offset. |
| T-002-01-02 | Elevation of Privilege | `MetalAcceleratorBufferBinder.inputDecisions` | mitigate | Accept existing device bindings only after policy classification plus `incompatibleBindingReason(...)` checks for dtype, shape, logical count, availability, and access. |
| T-002-01-03 | Repudiation | `AcceleratorBufferDecision` reason text | mitigate | Preserve stable `INPUT_LAYOUT_UNSUPPORTED`, `OUTPUT_LAYOUT_UNSUPPORTED`, and `NATIVE_BUFFER_ABI_UNAVAILABLE` reason codes with fake-bridge assertions. |
| T-002-01-04 | Information Disclosure | Trace diagnostics | accept | Layout diagnostics expose tensor shape/stride metadata only inside local execution traces; no network or multi-user boundary exists. |
</threat_model>
