<interfaces>
Existing native buffer ABI:
```java
int32_t synaptik_apple_mps_execute_partition_f32_buffers(
        void *context,
        void *executable,
        const void * const *external_input_buffers,
        int32_t external_input_count,
        void * const *output_buffers,
        int32_t output_count,
        int64_t *native_device_copy_ns
);
```

No new native ABI is required for this plan because MPSGraph receives dense `MTLBuffer` handles plus executable shape metadata. Java owns logical stride/offset correctness by:
1. allocating dense physical bytes sized to `layout.logicalByteLength()`;
2. attaching `MetalBufferBinding.layout()` as the logical target layout;
3. scattering dense readback into CPU tensor storage when `CpuMaterializationReason` requires CPU visibility.
</interfaces>
</context>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Java logical layout -> dense native buffer | Java metadata decides how dense native bytes map back into logical CPU tensor storage. |
| Native buffer handle -> CPU materializer | A device-owned binding can become user-visible CPU data. |
| Java FFM bridge -> Objective-C shim | ABI mismatch can silently turn expected buffer execution into fallback or wrong native writes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-002-02-01 | Tampering | `MetalBufferAllocator.readToCpu` | mitigate | Scatter dense bytes using target shape/strides/storageOffset with tests for permuted and non-zero-offset destinations. |
| T-002-02-02 | Spoofing | `MetalDeviceToCpuMaterializer.supports` | mitigate | Return true only for available Metal bindings whose logical layout exactly matches the target tensor and whose policy action is accepted. |
| T-002-02-03 | Repudiation | `PreparedMetalExecutable.markBufferOutputsCurrent` | mitigate | Promote device bindings only after native `executeBuffers(...)` succeeds and keep CPU materialization traces reason-labelled. |
| T-002-02-04 | Elevation of Privilege | Native ABI boundary | mitigate | Add no new native symbol in this plan; document and test that Java supplies dense physical buffers and handles logical materialization. |
| T-002-02-05 | Denial of Service | Layout scatter rank | mitigate | Reject ranks above 4 with a stable message matching the existing Metal native rank limit. |
</threat_model>
