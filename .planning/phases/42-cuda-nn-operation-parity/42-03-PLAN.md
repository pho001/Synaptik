# Plan 42-03: CUDA Dense Loss Parity

**Phase:** 42 CUDA NN Operation Parity
**Requirements:** CUDANN-03
**Status:** Planned
**Wave:** 3

## Objective

Give CUDA dense `NLL_LOSS` and dense `CROSS_ENTROPY_LOSS` a stable dense-loss contract matching Metal, with native execution only if the required lowered primitives and parity evidence exist.

## Tasks

1. Add CUDA dense loss semantic checks:
   - `FLOAT32` output, scores/log-probabilities, and dense targets;
   - dense zero-offset layouts;
   - rank 1..4;
   - valid class axis;
   - dense target shape equals score shape;
   - mean-reduced scalar output shape `[1]`.
2. Decide whether the current CUDA DAG primitive set can lower dense loss safely.
   - If yes, promote the rows only with native buffer execution and CPU parity tests.
   - If no, keep `DAG_PRIMITIVE_UNSUPPORTED` after stable dense-loss contract validation.
3. Keep index-target loss rows separate as `UNSUPPORTED_INDEX_SEMANTICS`.
4. Add tests for dense legal blocker, dtype, layout, rank, class-axis, target-shape, output-shape, and index-target separation.

## Acceptance Criteria

- Dense loss blockers are specific, stable, and separate from index-target loss blockers.
- No dense loss support claim exists without native/lowered CUDA execution evidence.
- `dense_loss_small` and `cross_entropy_small` remain distinct coverage targets.
