# Plan 42-01: CUDA SDPA Forward Parity

**Phase:** 42 CUDA NN Operation Parity
**Requirements:** CUDANN-01
**Status:** Planned
**Wave:** 1

## Objective

Give CUDA forward SDPA a stable support-or-rejection contract for unmasked, masked, and causal variants without claiming native execution until the CUDA bridge has evidence.

## Tasks

1. Add CUDA SDPA semantic classification under `backend/cuda/lowering/`.
2. Validate rank 3/4, dense `FLOAT32` query/key/value/output, scale metadata, broadcast batch compatibility, and output shape.
3. Validate mask inputs before capability rejection:
   - external mask must be `BOOL`;
   - mask layout must be dense;
   - mask shape must match broadcasted score shape;
   - causal and external+causal modes must be identified in detail text.
4. Keep final legal CUDA SDPA status as `CAPABILITY_MISSING` unless a real native/routed CUDA primitive is implemented in this plan.
5. Add tests proving invalid dtype/layout/rank/mask cases reject before generic capability-missing.

## Acceptance Criteria

- CUDA SDPA legal unmasked and masked candidates reach stable `CAPABILITY_MISSING` with `target=transformer_block_hot_path` or `target=masked_sdpa_small`.
- Invalid mask polarity/type/layout/shape produces `UNSUPPORTED_DTYPE`, `UNSUPPORTED_LAYOUT`, `UNSUPPORTED_RANK_OR_SHAPE`, or `UNSUPPORTED_MASK_SEMANTICS`.
- Coverage/matrix tests still do not count CUDA SDPA as supported without native execution.

  **Mitigation:** Mask classification must remain rejection-only unless native parity evidence exists.
