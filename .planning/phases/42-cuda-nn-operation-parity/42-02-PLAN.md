# Plan 42-02: CUDA Conv/Pool Forward Parity

**Phase:** 42 CUDA NN Operation Parity
**Requirements:** CUDANN-02
**Status:** Planned
**Wave:** 2

## Objective

Make CUDA forward `CONV2D`, `CONV2D_GEMM`, `MAX_POOL2D`, and `AVG_POOL2D` expose precise semantic blockers or real native execution evidence.

## Tasks

1. Add CUDA conv/pool semantic checks mirroring the scoped Metal contract:
   - dense `FLOAT32` inputs/output;
   - rank-4 NCHW input/output;
   - OIHW weights for conv;
   - optional bias shape `[outChannels]`;
   - groups/channel contract;
   - dilation, stride, padding, kernel metadata limits;
   - `AVG_POOL2D countIncludePad=false` only unless divisor semantics are implemented.
2. If no CUDA native conv/pool route exists, legal candidates must end in `CAPABILITY_MISSING` or `VENDOR_LIBRARY_ROUTE_NOT_INTEGRATED`.
3. Add tests for invalid dtype, non-dense layout, invalid rank/shape, groups, dilation, and avg-pool divisor blockers.
4. Keep conv/pool backward rows out of Phase 42 support.

## Acceptance Criteria

- CUDA conv/pool forward rows no longer return only generic matrix detail for invalid contracts.
- Legal forward rows remain explicit blocker rows unless a real native/routed execution path is added.
- Backward conv/pool rows remain `CAPABILITY_MISSING`.
