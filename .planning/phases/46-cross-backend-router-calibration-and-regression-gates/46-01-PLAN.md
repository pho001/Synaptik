# 46-01 Router Calibration Evidence Model

## Objective

Create a backend-neutral router evidence model derived from execution traces. It must aggregate route, dtype, layout, copy/write, fallback, and native capability evidence without changing execution behavior.

## Tasks

1. Add a report-side evidence model that reads existing trace attributes for Metal and CUDA.
2. Capture selected route/path counts, rejected route/capability reasons, dtype counts, layout materialization evidence, native copy strategy, output write status, tensor-array replay, CPU fallback, and internal CPU materialization.
3. Add focused tests using synthetic Metal and CUDA traces.
4. Keep old report/coverage APIs source-compatible where practical.

## Verification

- `./gradlew test --tests CrossBackendRouterEvidenceTest`
- `./gradlew classes`

## Completion Criteria

- A single evidence object can explain why a backend route was considered supported, explicit fallback, or rejected.
