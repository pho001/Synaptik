<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ExecutionContext -> Metal binder | Runtime tensors and prepared inputs become binding requests and backend preflight decisions. |
| Metal buffer binding -> native bridge | Java-side binding metadata controls whether native buffer execution is invoked. |
| CUDA policy -> fallback path | Required buffer mode can fail before tensor-list execution. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-001-02-01 | Tampering | `MetalAcceleratorBufferBinder.incompatibleBindingReason` | mitigate | Compare dtype, shape, strides, storage offset, element count, and access against the expected layout before accepting existing bindings. |
| T-001-02-02 | Denial of Service | `MetalBufferAllocator.createOutputBinding` | mitigate | Allocate from checked `layout.logicalByteLength()` and reject non-dense layout classes before native calls. |
| T-001-02-03 | Repudiation | `PreparedCudaExecutable` required mode | mitigate | Use `REQUIRED_BUFFER_EXECUTION_UNAVAILABLE` for required-but-unavailable CUDA buffer execution so traces and tests cannot confuse it with optional fallback. |
| T-001-02-04 | Elevation of Privilege | `CudaGraphBridge.supportsBufferBindings()` | accept | Local native bridge SPI has no auth surface; Javadoc contract prevents common-handle leakage and requires backend-owned native handles. |
</threat_model>
