# Plan 29-04: Docs, Tests, And Migration Closure

**Phase:** 29 Metal DType ABI And Capability Truth
**Requirements:** METALDTYPE-01, METALDTYPE-02, METALDTYPE-03
**Status:** Planned
**Wave:** 4

## Objective

Close Phase 29 with documentation, migration notes, and focused verification so Phase 30-32 can add dtype-specific execution without reopening ABI semantics.

## Tasks

1. Update `docs/metal-backend.md` with the dtype capability truth table and ABI v3 meaning.
2. Update `docs/gpu-lowering-coverage.md` to distinguish dtype residency, native dtype compute, output legality, and dtype fallback.
3. Add or update tests that cover:
   - full `DataType` role matrix,
   - optional dtype ABI v3 symbol behavior,
   - old `_f32` ABI compatibility,
   - FLOAT64 explicit unsupported decisions,
   - report/diagnostic rendering.
4. Write summaries for all Phase 29 waves with verification evidence.
5. Keep local profile/calibration artifacts unstaged.

## Acceptance Criteria

- Public docs state that current Metal native compute/output remains FLOAT32 unless later phases add support.
- Dtype ABI v3 is documented as capability discovery, not automatic execution support.
- Verification evidence maps directly to `METALDTYPE-01/02/03`.
- Phase 30-32 can reference a stable dtype ABI/capability contract.
