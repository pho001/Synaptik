<threat_model>
T-7-01: Partially present CUDA buffer symbols could overclaim native buffer support. Mitigation: `supportsBufferBindings()` requires create, read, destroy, execute-buffer symbols and the Java enablement flag.
T-7-02: Materializer could mark CPU storage current without copying bytes. Mitigation: `CudaDeviceToCpuMaterializer.materialize(...)` delegates to allocator read-back before returning success.
T-7-03: CUDA native resources could leak after execution. Mitigation: buffer handles are wrapped in `CudaBufferResource` and registered via `ExecutionContext.registerResource(...)` in later plans.
</threat_model>

    - `readToCpu` supports only `FLOAT32`, matching layout, direct output `float[]`, calls `nativeAccess.readBuffer(...)`, copies into `MemorySegment.ofArray(data)`, calls `destination.markDataViewStale()`, and returns `CpuMaterializationResult` with duration and detail containing `cuda read_buffer materialized nodeId=`.
