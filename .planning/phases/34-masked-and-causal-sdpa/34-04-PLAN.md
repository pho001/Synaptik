# Plan 34-04: Transformer Coverage Closure

**Phase:** 34 Masked And Causal SDPA
**Requirements:** METALSDPAMASK-02, METALSDPAMASK-03
**Status:** Planned
**Wave:** 4

## Objective

Close Phase 34 with benchmark/report evidence proving supported masked and causal transformer attention stays on Metal, while unsupported mask semantics remain visible and stable.

## Tasks

1. Add representative masked and causal transformer/attention workloads if existing workload names do not expose the required evidence.
2. Extend `GpuHotPathCoverageTargets` and regression gates with a `METALSDPAMASK` family target requiring:
   - native Metal buffer evidence,
   - masked/causal SDPA evidence,
   - lowered primitive count,
   - zero tensor-array fallback,
   - zero CPU fallback,
   - zero unexpected CPU materialization.
3. Extend coverage summary/report output with mask-mode evidence if not already available from manifest fields.
4. Update `docs/metal-backend.md`, `docs/gpu-lowering-coverage.md`, `docs/architecture.md`, and troubleshooting text from “masked SDPA rejected” to the scoped supported/rejected matrix.
5. Write `34-VERIFICATION.md` mapping `METALSDPAMASK-01..03` to implementation, parity, trace, and coverage evidence.
6. Keep local tuning/profile output unstaged unless intentionally promoting a canonical fixture.

## Acceptance Criteria

- Coverage gates fail if supported masked/causal attention exits to CPU, tensor-array replay, or hidden materialization.
- Docs state exactly which masked/causal SDPA variants are supported and which remain rejected.
- Phase 34 requirements are checked complete only after parity plus trace/report evidence exists.
- Profile artifacts under `profiles/platform/...` remain local unless explicitly promoted.

  **Mitigation:** Gates use trace/report fields, not speed, as closure proof.
- **Threat:** Docs overclaim universal masked SDPA.
  **Mitigation:** Coverage table separates supported external BOOL, causal, external+causal, unsupported dtype/layout/rank, and CUDA capability gaps.
