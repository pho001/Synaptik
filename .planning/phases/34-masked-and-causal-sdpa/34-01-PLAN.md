# Plan 34-01: Mask Semantics And Parity Contract

**Phase:** 34 Masked And Causal SDPA
**Requirements:** METALSDPAMASK-01
**Status:** Completed
**Wave:** 1

## Objective

Lock the semantic and diagnostic contract for masked and causal Metal SDPA before allowing planner admission. The output of this wave is a tested legality layer that still rejects unsupported cases, but with exact mask-mode and reason-code evidence instead of the current single `UNSUPPORTED_MASK_SEMANTICS` bucket.

## Tasks

1. Add a direct-SDPA mask semantics classifier covering:
   - unmasked direct SDPA,
   - external public `BOOL` mask,
   - causal-only effective mask,
   - external AND causal effective mask,
   - unsupported additive/floating public mask inputs,
   - unsupported rank, broadcast, dtype, and layout cases.
2. Refactor `MetalPartitionSupport.sdpaUnsupportedReason(...)` to use the classifier while preserving current unmasked support behavior.
3. Add stable diagnostic detail for mask blockers:
   - mask dtype unsupported,
   - mask shape/broadcast unsupported,
   - mask layout unsupported,
   - mask semantics unsupported by native ABI,
   - causal mask unsupported by native ABI.
4. Update tests that currently expect the old direct masked SDPA rejection string to assert the new precise reason.
5. Add CPU parity fixture expectations for the supported semantic modes, even if Metal execution is still rejected until Wave 2.

## Acceptance Criteria

- The codebase has one source of truth for direct SDPA mask semantics used by Metal planner legality.
- Existing unmasked Metal SDPA tests keep passing.
- Masked and causal direct SDPA still reject before native support, but the reason says exactly which semantic mode or blocker applied.
- CUDA behavior remains capability-gated and does not inherit Metal mask support claims.

## Threat Model

- **Threat:** A more detailed classifier accidentally admits masked SDPA before native semantics exist.
  **Mitigation:** Keep Wave 1 planner decisions unsupported for masked/causal direct SDPA unless an executable mask mode is explicitly enabled.
- **Threat:** Causal support is confused with an already-expanded external mask.
  **Mitigation:** Classifier names the observed effective mask mode and tests causal-only plus external+causal construction.
