# Plan 32-03: Bounds Layout Parity And Visible Rejections

**Phase:** 32 INT32 Index Tensor And Gather Take Path
**Requirements:** METALINTIDX-02, METALINTIDX-03
**Status:** Planned
**Wave:** 3

## Objective

Lock gather/take bounds, axis, dtype, and layout behavior so Metal support matches CPU for legal cases and rejects unsupported cases visibly.

## Tasks

1. Add CPU-vs-Metal parity tests for valid `GATHER` and `TAKE_ALONG_AXIS` cases across representative axes and ranks.
2. Add explicit tests for out-of-bounds, invalid index dtype, invalid rank/axis, non-dense value input, non-dense index input, and unsupported output/value dtype.
3. Ensure rejection details use stable reason codes such as `UNSUPPORTED_DTYPE`, `UNSUPPORTED_LAYOUT`, `UNSUPPORTED_RANK_OR_SHAPE`, or `UNSUPPORTED_BOUNDS_CHECK`.
4. Verify adjacent supported Metal producers/consumers around gather/take remain device-owned with no avoidable `CPU_CONSUMER` materialization.
5. Keep gradient/scatter variants rejected with duplicate-index reason codes until Phase 36.

## Acceptance Criteria

- Legal forward index cases match CPU output exactly or within dtype-appropriate tolerance.
- Unsupported bounds/layout/dtype/rank cases reject or fallback with stable report-visible details.
- Adjacent legal Metal regions preserve device residency across gather/take.
- Backward/scatter index ops remain explicit unsupported rows.

## Threat Model

- **Threat:** Out-of-bounds native behavior is undefined or differs from CPU.
  **Mitigation:** Validate/reject bounds before native execution when bounds cannot be proven safe.
- **Threat:** Non-dense index/value inputs trigger hidden CPU layout repair.
  **Mitigation:** Reject unsupported layouts in planner or report explicit GPU layout materialization only when Phase 33 router support exists.
