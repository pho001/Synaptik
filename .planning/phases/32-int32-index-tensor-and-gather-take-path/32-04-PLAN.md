# Plan 32-04: Coverage Docs And Regression Closure

**Phase:** 32 INT32 Index Tensor And Gather Take Path
**Requirements:** METALINTIDX-01, METALINTIDX-02, METALINTIDX-03
**Status:** Planned
**Wave:** 4

## Objective

Close Phase 32 with coverage targets, regression gates, docs, and verification evidence that prove supported Metal index-forward paths stay native and unsupported paths remain visible.

## Tasks

1. Add or promote a representative gather/take hot-path coverage target with `METALINTIDX` requirement family.
2. Add regression gates requiring native Metal buffer execution, lowered primitive evidence, `dtype=INT32` residency evidence, zero tensor-array fallback, zero CPU fallback, and no unexpected CPU materialization.
3. Keep CUDA expectations as visible blockers for gather/take until a CUDA implementation lands.
4. Update `docs/metal-backend.md`, `docs/gpu-lowering-coverage.md`, and troubleshooting docs with scoped INT32 index support and explicit non-goals.
5. Write `32-VERIFICATION.md` mapping `METALINTIDX-01/02/03` to implementation, tests, trace/report fields, and docs.
6. Verify local profile artifacts remain unstaged.

## Acceptance Criteria

- Reports distinguish INT32 index-input residency from native INT32 arithmetic compute.
- Supported Metal gather/take target gates fail hidden CPU exits and missing INT32 evidence.
- Docs do not claim scatter, gradients, loss-index, CUDA parity, or generic INT32 compute/output support.
- Phase 32 requirements have traceable verification evidence.

- **Threat:** Local benchmark artifacts are committed accidentally.
