# Plan 32-02: Forward Gather Take Lowering And Native Execution

**Phase:** 32 INT32 Index Tensor And Gather Take Path
**Requirements:** METALINTIDX-02
**Status:** Completed
**Wave:** 2

## Objective

Add shared accelerator DAG nodes and native Metal execution for scoped forward `GATHER` and `TAKE_ALONG_AXIS` with `INT32` indices.

## Tasks

1. Add accelerator DAG ABI node types for `GATHER` and `TAKE_ALONG_AXIS`, including axis metadata.
2. Extend `AcceleratorSubgraphLowerer` to lower legal forward index ops with value input, index input, output shape, dtype, and axis metadata.
3. Update `GpuLoweringCoverageMatrix` so Metal forward `GATHER`/`TAKE_ALONG_AXIS` can become supported only when native execution evidence exists; keep CUDA unsupported.
4. Implement native Objective-C MPSGraph shim branches for the scoped forward cases, or keep the row capability-missing if the local SDK cannot provide a verified primitive.
5. Add Java FFM/native tests for exact CPU parity on representative axis/rank cases.
6. Ensure selected Metal regions can combine producer value ops plus gather/take without materializing the value input before the index op.

## Acceptance Criteria

- Legal dense forward `GATHER` and `TAKE_ALONG_AXIS` lower to shared DAG primitives.
- Native Metal execution returns CPU-parity values for representative valid index cases.
- CUDA and unsupported Metal variants continue to reject with stable visible reasons.
- `INT32` index input residency appears in lowering/trace evidence.

## Threat Model

- **Threat:** MPSGraph gather semantics differ from CPU gather/take semantics.
  **Mitigation:** Native parity tests must cover output shape, axis metadata, and representative index ordering before support is claimed.
- **Threat:** Lowering admits a shape/rank that native code cannot execute.
  **Mitigation:** Planner legality and native descriptor validation must share the same rank/axis constraints.
