# Plan 41-02: CUDA Layout Router And Materialization Parity

**Phase:** 41 CUDA DType Layout And Index Residency
**Requirements:** CUDADTYPE-02
**Status:** Planned
**Wave:** 2

## Objective

Make CUDA layout routing decisions as explicit as Metal: metadata-only views, legal dense GPU materialization, unsupported broadcast/strided compute, and CPU materialization boundaries must be distinguishable in traces and tests.

## Tasks

<tasks>
<task id="41-02-01" type="execute">
<read_first>
- `src/main/java/backend/accelerator/buffer/AcceleratorLayoutTransformPlanner.java`
- `src/main/java/backend/accelerator/buffer/AcceleratorLayoutTransformDecision.java`
- `src/main/java/backend/cuda/buffer/CudaDeviceLayoutMaterializer.java`
- `src/main/java/backend/metal/buffer/MetalDeviceLayoutMaterializer.java`
</read_first>
<action>
Audit shared layout transform decisions and CUDA materializer behavior.

Keep CUDA support conservative:
- `METADATA_ONLY_VIEW` remains supported through binding metadata when the consumer can later be made legal.
- `DENSE_GPU_MATERIALIZATION` remains supported only for dense `FLOAT32` target layouts and bridge materialization capability.
- `BROADCAST_GPU_MATERIALIZATION` must reject on CUDA unless the native CUDA materializer actually implements it.
- `STRIDED_NATIVE_COMPUTE` remains unsupported for CUDA compute.

Improve CUDA materializer exceptions to include stable prefixes such as `NATIVE_LAYOUT_DTYPE_UNSUPPORTED`, `CUDA_LAYOUT_BROADCAST_UNSUPPORTED`, and `CUDA_STRIDED_COMPUTE_UNSUPPORTED` where applicable.
</action>
<acceptance_criteria>
- CUDA materializer has explicit rejection text for unsupported materialization kind, dtype, and target layout.
- Dense `FLOAT32` materialization behavior remains unchanged.
- No CUDA code claims generic native strided compute support.
</acceptance_criteria>
</task>

- metadata-only view that still needs materialization;
- non-dense direct compute input;
- dtype-role mismatch;
- stale/non-current runtime residency;

Do not move expensive runtime checks into prepare; this plan only improves static/router diagnostics and fast validation messaging.
</action>

## Success Criteria

- CUDADTYPE-02 has CUDA-specific layout routing evidence.
- Layout repair and layout rejection are reportable separately from dtype residency.
- CUDA does not overclaim broadcast or arbitrary strided native compute.

## Threat Model

- **T41-03:** Metadata-only CUDA view could be used directly by a native compute primitive that requires dense storage.
  **Mitigation:** Binding compatibility diagnostics keep metadata-only views materialization-required for dense-only consumers.
- **T41-04:** Broadcast repair could be counted as supported because Metal supports it.
  **Mitigation:** CUDA tests keep broadcast repair explicitly unsupported until native CUDA implementation exists.
