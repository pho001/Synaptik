# Plan 41-03: CUDA Forward Gather/Take Execution Or Stable Rejection

**Phase:** 41 CUDA DType Layout And Index Residency
**Requirements:** CUDAINDEX-01
**Status:** Planned
**Wave:** 3

## Objective

Close the Phase 41 CUDA forward index path at a support-or-rejection standard: either implement scoped forward `GATHER` / `TAKE_ALONG_AXIS` native execution, or produce stable CUDA rejection evidence that preserves adjacent GPU producers and explains why the region shortened.

## Tasks

<tasks>
<task id="41-03-01" type="execute">
<read_first>
- `src/main/java/backend/metal/lowering/MetalPartitionSupport.java`
- `src/main/java/backend/cuda/lowering/CudaGpuRegionLegalityAdapter.java`
- `src/main/java/backend/accelerator/lowering/GpuLoweringCoverageMatrix.java`
- `src/main/java/operations/index/gather.java`

<action>
Create `CudaPartitionSupport` under `src/main/java/backend/cuda/lowering/` and move CUDA-specific legality details there, starting with forward `GATHER` and `TAKE_ALONG_AXIS`.

The CUDA index contract must validate before choosing support or stable rejection:
- operation is `GATHER` or `TAKE_ALONG_AXIS`;
- value input and output are dense `FLOAT32`;
- index input is dense `INT32`;
- rank/axis/shape rules match public CPU semantics;
- static leaf index bounds can be proven, or rejection is `UNSUPPORTED_BOUNDS_CHECK`;
- direct non-dense value/index inputs reject with `UNSUPPORTED_LAYOUT`;
- generic `INT32` compute/output remains unsupported.
</action>
<acceptance_criteria>
- `CudaPartitionSupport.java` exists and contains `indexUnsupportedReason`.
- Rejection strings include `UNSUPPORTED_DTYPE`, `UNSUPPORTED_LAYOUT`, `UNSUPPORTED_RANK_OR_SHAPE`, `UNSUPPORTED_BOUNDS_CHECK`, and `CAPABILITY_MISSING`.
- `CudaGpuRegionLegalityAdapter` delegates CUDA index legality to `CudaPartitionSupport`.
</acceptance_criteria>
</task>

<task id="41-03-02" type="execute">
<read_first>

<action>
Evaluate whether scoped CUDA forward index execution is feasible within Phase 41 without adding an unsafe native contract.

If feasible, implement the narrow path:
- lower `GATHER` / `TAKE_ALONG_AXIS` to existing DAG node types;
- add native CUDA execution for dense `FLOAT32` values and dense static `INT32` indices;
- prove CPU parity on representative rank/axis cases.

If not feasible, keep coverage rows unsupported and wire stable rejection after contract validation:
- legal candidate reaches final `CAPABILITY_MISSING` detail;
- invalid dtype/layout/bounds/rank cases fail before capability-missing detail;
- adjacent CUDA producers can remain selected independently when the index op is shortened out.
</action>
<acceptance_criteria>
- Either native CUDA index execution has parity tests, or the matrix/docs explicitly retain `CAPABILITY_MISSING`.
- Stable rejection is more specific than a generic matrix fallback for dtype/layout/bounds/rank mistakes.
- No support row is promoted without native execution or routed primitive evidence.
</acceptance_criteria>
</task>

<action>
Add tests for CUDA forward index behavior.

Required cases:
- legal dense `FLOAT32` value + dense static in-bounds `INT32` indices reaches either native support or final `CAPABILITY_MISSING`;
- `FLOAT32` indices reject with `UNSUPPORTED_DTYPE`;
- out-of-bounds static indices reject with `UNSUPPORTED_BOUNDS_CHECK`;
- non-dense value/index layout rejects with `UNSUPPORTED_LAYOUT`;
- gather/take gradients and scatter remain `UNSUPPORTED_DUPLICATE_INDEX`;
- an adjacent CUDA-supported producer can still form a CUDA region when the index consumer is unsupported.
</action>
<acceptance_criteria>
- Tests distinguish forward `GATHER` / `TAKE_ALONG_AXIS` from `GATHER_GRAD`, `TAKE_ALONG_AXIS_GRAD`, and `SCATTER_ADD`.
- Tests prove no hidden CPU fallback is counted as CUDA support.
- Existing Metal forward gather/take tests are unaffected.
</acceptance_criteria>
</task>

## Success Criteria

- CUDAINDEX-01 is satisfied through scoped execution or stable rejection evidence.
- CUDA index diagnostics are specific enough for coverage triage.
- Adjacent GPU producers are not forced to CPU solely because a later index consumer remains unsupported.

## Threat Model

- **T41-05:** CUDA gather/take could claim support without CPU-compatible bounds behavior.
  **Mitigation:** Bounds validation is required before support or final capability-missing rejection.
- **T41-06:** Forward index support could be confused with scatter/index-gradient support.
  **Mitigation:** Tests and matrix keep gradient/write rows on `UNSUPPORTED_DUPLICATE_INDEX`.
