# Plan 38-03: Training Trace And Gradient Publication Gates

**Phase:** 38 Metal Training Backward Coverage
**Requirements:** METALTRAIN-02, METALTRAIN-03
**Status:** Complete
**Wave:** 3

## Objective

Add training-specific trace and coverage gates that permit true gradient publication boundaries but fail avoidable internal CPU materialization inside supported Metal training regions.

## Tasks

1. Add or extend hot-path training targets for representative `FORWARD_BACKWARD` workloads:
   - transformer block or attention-heavy training path
   - MLP/dense loss training path
   - normalization/reduction training path
   - index/scatter/loss blocker path
2. Extend coverage gate policy so it can distinguish:
   - allowed `GRADIENT_PUBLICATION`
   - unexpected `CPU_CONSUMER`
   - CPU fallback steps
   - tensor-array bridge replay
   - shortened selected Metal backward regions
3. Add report fields or target expectations for backward lowered primitive count, backward region count, and gradient publication materialization count.
4. Add tests proving supported training paths stay Metal-owned until the real publication boundary.
5. Add tests proving unsupported backward paths remain report-visible with stable reasons.

## Acceptance Criteria

- Training hot-path gates fail hidden internal CPU materialization.
- Gradient publication is counted separately from avoidable CPU exits.
- Reports make supported backward work and unsupported backward blockers audit-readable.

## Threat Model

- **Threat:** Legitimate gradient publication is treated as a regression, causing gates to become unusable.
  **Mitigation:** Gate policy must separate materialization reasons and only fail unexpected internal CPU exits.
