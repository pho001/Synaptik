# Plan 30-01: BF16 Storage, ABI, And Materialization Path

**Phase:** 30 BF16 Metal Compute And Output
**Requirements:** METALBF16-01, METALBF16-02
**Status:** Planned
**Wave:** 1

## Objective

Make BF16 representable across the Metal DAG/native transport path without yet broadening every operation family.

## Tasks

1. Add output dtype metadata to the lowered accelerator DAG contract or bridge compile descriptor.
2. Include output dtype metadata in `AcceleratorSubgraphSignature` so BF16 and FLOAT32 executables cannot share the wrong native cache entry.
3. Add BF16 dtype code mapping for native execution ABI use, distinct from Phase 29 descriptor-only codes.
4. Extend the native shim to map BF16 dtype code to `MPSDataTypeBFloat16` where available.
5. Extend `MetalBufferAllocator` to upload/read raw BF16 `short[]` data and allocate BF16 output bindings.
6. Extend buffer binding validation to accept BF16 only when executable dtype metadata expects BF16.
7. Add tests for BF16 input binding, output allocation, readback/materialization, executable dtype validation, and FLOAT32 path stability.

## Acceptance Criteria

- BF16 storage can be uploaded to and read from Metal buffers without byte reinterpretation as FLOAT32 or float16.
- Native executable metadata preserves BF16 output dtype.
- Missing or unsupported BF16 native dtype capability rejects visibly.
- Existing FLOAT32 buffer execution tests remain unchanged.

## Verification

./gradlew test --tests backend.metal.MetalMpsCapabilitiesTest --tests backend.metal.bridge.MetalMpsFfmBridgeTest --tests backend.metal.exec.PreparedMetalExecutableBufferBindingTest
./gradlew metalTest

## Must Haves

- METALBF16-02: BF16 buffer binding and materialization preserve CPU BF16 storage semantics.
- METALBF16-01: BF16 native admission has the ABI metadata needed for operation-specific support.

## Threat Model

- **Threat:** BF16 and FLOAT32 executable cache entries collide.
  **Mitigation:** Add output dtype metadata to signature keys.
- **Threat:** BF16 bytes are treated as IEEE float16 or FLOAT32.
  **Mitigation:** Use raw `short[]` storage and explicit dtype codes/tests.
