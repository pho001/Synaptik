<objective>
Add the backend-neutral Java manifest model and stable DAG-level reason vocabulary for selected GPU lowered regions.
</objective>

<source_audit>
GOAL: Defines a GPU region as a lowered DAG manifest instead of a single op or opaque compound label.
REQ GPUDAG-01: Covered by a manifest that supports multi-op region ids, ordered original ops, and ordered lowered primitives.
REQ GPUDAG-02: Covered by records for original op ids/types, primitive ids/types, backend id, dtype/layout/storage assumptions, fused summary, and selected region length.
REQ GPUDAG-03: Covered by `GpuLoweredRegionRejection`, `GpuLoweredRegionCandidateSpan`, and DAG-level `GpuLoweringUnsupportedReason` codes.
CONTEXT D-01, D-02, D-03, D-05, D-06, D-07, D-08, D-13, D-14, D-15, D-16 are implemented by this model layer.
</source_audit>

<threat_model>
T-15-01: Debug/report metadata could be pushed into `AcceleratorDagSpec` and accidentally alter native bridge semantics. Mitigation: add separate `GpuLoweredRegionManifest` records under `backend.accelerator.lowering` and keep `AcceleratorDagSpec` unchanged.
T-15-02: Rejection reasons could become free-form strings that Phase 20 cannot gate. Mitigation: extend `GpuLoweringUnsupportedReason` with exact DAG-level enum constants and make rejection records store the enum code.
T-15-03: Manifest model could imply public GPU tensor/device API. Mitigation: keep all new classes under internal accelerator lowering packages and do not touch `tensor.Tensor`.
</threat_model>
