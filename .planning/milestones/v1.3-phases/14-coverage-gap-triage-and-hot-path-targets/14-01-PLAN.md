<objective>
Add the backend-neutral GPU coverage gap triage model that converts existing `GpuCoverageSummary` and benchmark reports into deterministic ranked gap records.
</objective>

<source_audit>
GOAL: Builds the ranking foundation for Phase 14 using v1.2 coverage evidence.
REQ GPUTRIAGE-01: Covered by extracting rejected candidate, fallback, CPU materialization, tensor-array, and device handoff reasons by backend and workload.
REQ GPUTRIAGE-03: Covered by deterministic severity scoring and requirement-family classification for downstream v1.3 work.
</source_audit>

<threat_model>
T-14-01: Triage could report generic accelerator presence while CPU exits remain hidden. Mitigation: `GpuCoverageGapCategory` must separate `CPU_MATERIALIZATION`, `TENSOR_ARRAY_FALLBACK`, `CPU_FALLBACK`, and `DEVICE_HANDOFF`.
T-14-02: Ranking could become subjective or timing-dependent. Mitigation: `GpuCoverageGapTriage` must use deterministic score constants and preserve raw counts in every `GpuCoverageGap`.
T-14-03: CUDA evidence could require local CUDA hardware. Mitigation: tests must use synthetic CUDA traces from existing report fixtures.
</threat_model>

  <action>
    Add final utility class `GpuCoverageGapTriage` with a private constructor and exact public static methods:
    - `List<GpuCoverageGap> fromReport(BenchmarkReport report)`
    - `List<GpuCoverageGap> fromSuite(BenchmarkSuiteReport report)`
    - `List<GpuCoverageGap> topGaps(BenchmarkSuiteReport report, int limit)`
    - `String requirementFamilyFor(GpuCoverageGapCategory category, String reason)`

    Derivation rules:
    - For every successful candidate with a non-null measurement, compute `GpuCoverageSummary.fromTrace(candidate.measurement().trace())`.
    - Create `REJECTED_CANDIDATE` gaps for every `rejectedCandidateReasonCounts` entry.
    - Create `CPU_MATERIALIZATION` gaps for every `cpuMaterializationReasonCounts` entry.
    - Create `TENSOR_ARRAY_FALLBACK` gap when `tensorArrayStepCount > 0` with reason `tensor-array fallback`.
    - Create `CPU_FALLBACK` gap when `cpuFallbackStepCount > 0` with reason `cpu fallback`.
    - Create `DEVICE_HANDOFF` gap when `deviceHandoffCount > 0` with reason `device handoff`.
    - Create `LOW_REGION_LENGTH` gap when `maxSelectedRegionLength < 3` with reason `short selected region`.
    - Create `LOW_GPU_COVERAGE` gap when `gpuCoverageRatio < 0.5d` with reason `low gpu coverage ratio`.
    - Create `STORAGE_RESIDENCY` gaps for non-`DEVICE_OWNED` storage residency counts.

    Severity score constants must be exact:
    - `CPU_MATERIALIZATION`: `1000 * count`
    - `TENSOR_ARRAY_FALLBACK`: `900 * count`
    - `CPU_FALLBACK`: `850 * count`
    - `DEVICE_HANDOFF`: `700 * count`
    - `REJECTED_CANDIDATE`: `500 * count`
    - `LOW_REGION_LENGTH`: `300`
    - `LOW_GPU_COVERAGE`: `250`
    - `STORAGE_RESIDENCY`: `200 * count`

    Sort output by:
    - descending `severityScore`
    - ascending `workloadName`
    - ascending `backend`
    - ascending `category.name()`
    - ascending `reason`
  </action>
