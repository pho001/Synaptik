<objective>
Connect the hard coverage gate to the Phase 14 hot-path target registry so Phase 20 enforces the milestone's selected workloads.
</objective>

<source_audit>
REQ GPUHARDEN-01: Covered by target expectations that name required report fields per workload.
REQ GPUHARDEN-02: Covered by suite-level tests that fail target policies on shortened regions and lost lowered/fused coverage.
REQ GPUHARDEN-03: Covered by explicit blocker-evidence policy for conv/normalization targets.
D-02: Gate policies cover the Phase 14 workload names exactly.
D-08: `transformer_block_hot_path` is the primary hardening target.
D-09: `mlp_classifier_small` is the secondary hardening target.
D-10: `conv2d_resnet_3x3` and `layer_norm_small` preserve visible blocker evidence when still partially unsupported.
D-11: Partially blocked targets assert explicit blocker reasons and report fields instead of pretending unsupported native execution exists.
</source_audit>

<threat_model>
T-20-03: Later code could gate opportunistic workload names instead of the Phase 14 source-of-truth targets. Mitigation: target policies must derive from `GpuHotPathCoverageTargets.defaultWorkloadNames()`.
T-20-04: Conv/norm targets could be weakened until they check nothing. Mitigation: partial targets must assert explicit rejection/materialization reason evidence.
</threat_model>
