# Plan 25-01: Forward SDPA Semantics And Parity Contract

**Phase:** 25 Forward SDPA Semantic Enablement
**Requirements:** GPUSDPA-01, GPUSDPA-02
**Status:** Planned
**Wave:** 1

## Objective

Lock the exact supported forward SDPA semantics before planner admission changes: scale behavior, rank conventions, output shape, mask/no-mask handling, dtype/layout legality, and backward interaction.

## Tasks

1. Extend `GpuTargetSemanticsContract` for `SCALED_DOT_PRODUCT_ATTENTION` from a blocker-only note into a phase-ready contract that enumerates supported dtype set, ranks, shape relationships, scale semantics, mask cases, layout legality, numerical tolerance, and backward/training interaction.
2. Add focused parity fixtures for CPU SDPA:
   - unmasked rank-3 explicit scale,
   - unmasked rank-4 default scale,
   - causal mask,
   - external BOOL mask,
   - invalid rank/shape/dtype cases.
3. Add tests proving current planner blockers are stable until later backend waves enable a legal case.
4. Define stable reason prefixes for unsupported SDPA variants: `UNSUPPORTED_DTYPE`, `UNSUPPORTED_LAYOUT`, `UNSUPPORTED_RANK_OR_SHAPE`, `UNSUPPORTED_MASK_SEMANTICS`, `CAPABILITY_MISSING`, and `BACKWARD_CONTEXT_UNSUPPORTED`.
5. Update docs that describe the SDPA contract, but keep the coverage matrix fallback state unchanged in this wave.

## Acceptance Criteria

- `GpuTargetSemanticsContractTest` verifies forward SDPA semantics are explicit and still gate planner admission.
- `AttentionExecutionTest` or a new focused test class covers CPU parity for rank, scale, and mask cases.
- Metal and CUDA legality tests still reject direct forward SDPA before backend execution evidence exists.
- Docs distinguish unmasked, causal, and external BOOL mask semantics.

## Verification

```bash
./gradlew test --tests GpuTargetSemanticsContractTest --tests AttentionExecutionTest --tests backend.metal.lowering.MetalRegionLowererTest --tests backend.cuda.lowering.CudaRegionLowererTest
```

## Must Haves

- GPUSDPA-01: scale, rank, mask/no-mask behavior, dtype support, and backward interaction are test-visible before admission.
- GPUSDPA-02: unsupported cases have stable capability-specific reasons.

## Threat Model

- **Threat:** Native admission starts from an ambiguous SDPA contract and silently accepts the wrong scale or mask semantics.
  **Mitigation:** CPU parity and contract tests land before matrix/planner support changes.
- **Threat:** Masked SDPA is accidentally treated like unmasked SDPA.
  **Mitigation:** Masked and unmasked cases get separate tests and stable reason codes.
