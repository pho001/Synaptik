# Plan 25-02: Metal Forward SDPA Admission Or Stable Rejection

**Phase:** 25 Forward SDPA Semantic Enablement
**Requirements:** GPUSDPA-01, GPUSDPA-02, GPUSDPA-03
**Status:** Planned
**Wave:** 2
**Depends on:** 25-01

## Objective

Resolve the Metal direct forward SDPA blocker honestly: either admit a narrow verified unmasked FLOAT32 path through MPSGraph/native DAG execution or keep direct SDPA rejected with stronger parity-backed evidence and decomposed GPU fragment coverage where legal.

## Tasks

1. Add Metal native parity tests for direct unmasked FLOAT32 rank-3 and rank-4 SDPA using the existing MPSGraph native `SDPA` switch.
2. Compare native Metal output against CPU SDPA for explicit scale and default-scale resolved values.
3. If parity passes:
   - update `MetalPartitionSupport` to admit only the verified unmasked legal contract,
   - keep unsupported dtype/layout/rank/shape/mask cases rejected with stable prefixes,
   - update `GpuLoweringCoverageMatrix` and `GpuTargetCoverageTruth` for Metal only.
4. If parity fails:
   - keep direct Metal SDPA fallback/rejected,
   - strengthen tests/docs with the exact observed blocker,
   - ensure decomposed legal attention fragments can still stay on GPU where the region does not require a direct SDPA node.
5. Preserve backward/training safety:
   - forward SDPA inside backward regions remains rejected unless explicitly proven safe,
   - prepared Metal fallback decisions stay visible when backward contains forward SDPA DAGs.
6. Update `PreparedExecutionBuildTest`, `CompiledGraphTraceTest`, and Metal lowering tests for the selected path.

## Acceptance Criteria

- Metal native gate either proves direct SDPA CPU parity and admits the exact legal case, or documents and tests a stable explicit rejection.
- Masked direct SDPA remains rejected unless a BOOL-mask-to-native-mask contract is implemented and parity-tested.
- Coverage matrix does not claim Metal support unless `PreparedMetalExecutable` can execute the legal path without hidden CPU materialization.
- Backward/training safety tests remain green.

## Must Haves

- GPUSDPA-01: Metal semantics are proven or explicitly blocked.
- GPUSDPA-02: Metal executes supported SDPA or rejects with stable capability-specific reasons.

## Threat Model

- **Threat:** MPSGraph `scale` behavior differs from CPU SDPA but planner admission hides the mismatch.
  **Mitigation:** Native Metal parity is the gate before support status changes.
- **Threat:** Backward execution accidentally routes a forward SDPA DAG through an unsafe Metal bridge path.
  **Mitigation:** Preserve and test backward-context SDPA rejection/fallback decisions.
