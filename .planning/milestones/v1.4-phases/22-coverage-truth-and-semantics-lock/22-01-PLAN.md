# Plan 22-01: Operation-Family Coverage Truth Table

**Phase:** 22 Coverage Truth And Semantics Lock
**Requirements:** GPUNATIVE-01, GPUNATIVE-03
**Status:** Complete

## Objective

Add a checked-in source-of-truth view that classifies each v1.4 target family by backend as one of:

- native buffer executable
- tensor-array bridge executable
- explicit CPU fallback
- unsupported rejection
- candidate-shortening risk

This must be derived from existing lowering coverage, DAG node support, backend capability, and runtime execution path evidence rather than a manually optimistic list.

## Tasks

1. Add a small backend-neutral target coverage model for v1.4 operation families.
2. Populate it from the current matrix and known executable DAG/native support.
3. Render a stable text/JSON coverage-truth section in benchmark or coverage reports.
4. Add focused tests proving the listed fallback families are not mislabeled as native execution.
5. Update docs or planning evidence to state that v1.3 rejection evidence is now v1.4 input, not completion.

## Acceptance Criteria

- Tests fail if `SUM`, `MEAN`, `REDUCE_MIN`, `REDUCE_MAX`, `LAYER_NORM`, `RMS_NORM`, forward SDPA, loss-adjacent, conv/pool, gather/scatter/index, or BOOL compare outputs are reported as native executable before backend execution exists.
- Report output distinguishes `SUPPORTED_BY_MATRIX` from `NATIVE_EXECUTABLE` if both concepts are present.
- Existing accelerator coverage tests still pass.
