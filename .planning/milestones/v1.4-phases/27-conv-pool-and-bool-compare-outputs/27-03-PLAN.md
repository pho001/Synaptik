# 27-03 Conv Pool Support-Or-Rejection Contract

## Objective

Make conv/pool GPU admission support-or-rejection explicit for representative workloads.

## Tasks

- Add planner diagnostics for `CONV2D`, `CONV2D_GEMM`, `MAX_POOL2D`, and `AVG_POOL2D`.
- Keep backend-specific native execution rejected with capability-gated reasons until real primitives/library routing exist.
- Run CPU parity tests for representative conv and pool workloads as the correctness baseline.

## Acceptance

- Metal/CUDA planner tests report `CAPABILITY_MISSING` for conv/pool targets instead of generic missing rows.
- Conv/pool CPU parity tests remain green.
- Coverage docs describe required future native work before support can be claimed.
