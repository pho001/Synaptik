# Plan 26-03: Gather Take Scatter Support-Or-Rejection

**Phase:** 26 Loss-Adjacent And Indexing GPU Coverage
**Requirements:** GPULOSSIDX-01, GPULOSSIDX-02, GPULOSSIDX-03
**Status:** Planned
**Wave:** 3

## Objective

Evaluate index primitives for safe GPU admission. Implement only cases that can be executed natively with CPU parity; otherwise preserve precise stable rejection.

## Tasks

1. Assess `GATHER` and `TAKE_ALONG_AXIS` as the safest forward-only candidates.
2. If implemented, add DAG ABI codes, Java lowering, Metal native execution, CUDA native execution, legality tests, and CPU parity tests for dense `FLOAT32` values plus `INT32` indices.
3. Keep `SCATTER_ADD`, `GATHER_GRAD`, and `TAKE_ALONG_AXIS_GRAD` unsupported unless duplicate-index accumulation parity is implemented.
4. If native support is not implemented in this phase, add stable support-or-rejection tests proving why each operation remains CPU-owned.

## Acceptance Criteria

- Any supported index row has real backend execution evidence.
- Duplicate-index accumulation semantics are never marked supported without parity.
- Unsupported cases retain visible stable reasons.
- CPU parity tests cover boundary and duplicate-index behavior.

## Verification

./gradlew test --tests GatherExecutionTest --tests TakeAlongAxisExecutionTest --tests ScatterAddExecutionTest --tests backend.metal.lowering.MetalRegionLowererTest --tests backend.cuda.lowering.CudaRegionLowererTest
```

```

## Threat Model

- **Threat:** Forward gather looks easy but shape/axis/bounds semantics diverge from CPU.
  **Mitigation:** Require parity and bounds tests before support.
- **Threat:** Scatter duplicate-index accumulation is nondeterministic or order-sensitive.
  **Mitigation:** Keep scatter/grad rows unsupported until deterministic semantics are proven.
