# Plan 26-01: Loss And Indexing Semantics Coverage Contract

**Phase:** 26 Loss-Adjacent And Indexing GPU Coverage
**Requirements:** GPULOSSIDX-01, GPULOSSIDX-03
**Status:** Planned
**Wave:** 1

## Objective

Make loss/indexing coverage truthful and complete before any support claims: every target op has a backend row, stable reason, and semantics contract.

## Tasks

1. Add stable unsupported reason vocabulary for loss/indexing semantics where existing generic codes are too broad.
2. Expand `GpuLoweringCoverageMatrix` rows for `GATHER_GRAD`, `TAKE_ALONG_AXIS`, and `TAKE_ALONG_AXIS_GRAD`.
3. Refine existing loss/index rows so notes identify index target dtype, ignore-index/reduction semantics, duplicate-index accumulation, and missing native primitive support.
4. Update `GpuTargetSemanticsContract` text to distinguish resident index tensors from native index/loss compute support.
5. Add matrix/contract tests for all Phase 26 rows and reason codes.
6. Update `docs/gpu-lowering-coverage.md`.

## Acceptance Criteria

- Matrix tests enumerate all Phase 26 loss/index ops for both Metal and CUDA.
- Unsupported rows have stable reason codes and operation-specific notes.
- Docs no longer imply that only `GATHER` and `SCATTER_ADD` represent the index family.
- No row is marked `SUPPORTED` without native execution evidence.

## Verification

```bash
./gradlew test --tests backend.accelerator.lowering.GpuLoweringCoverageMatrixTest --tests GpuTargetSemanticsContractTest
```

## Threat Model

- **Threat:** A coverage row becomes a false positive.
  **Mitigation:** Keep status non-supported until native DAG and backend execution are implemented and tested.
- **Threat:** Risky index semantics are hidden by generic `UNSUPPORTED_OPERATION`.
  **Mitigation:** Add stable reason codes and tests for the exact family blockers.
