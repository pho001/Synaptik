# Plan 28-01: Target Coverage Policy Audit

**Phase:** 28 Coverage Regression Closure
**Requirements:** GPUCLOSE-01, GPUCLOSE-02
**Status:** Planned
**Wave:** 1

## Objective

Align every v1.4 hot-path target expectation with the actual execution truth from Phases 23-27 so supported families get hard native/buffer gates and unsupported families require visible rejection reasons.

## Tasks

1. Audit `GpuHotPathCoverageTargets.expectationsForBackend(...)` against `GpuTargetCoverageTruth` and Phase 23-27 verification artifacts.
2. Promote `reduction_chain_small` from permissive partial-blocker policy to a supported native/lowered policy for legal Metal/CUDA cases:
   - require native buffer binding,
   - require nonzero selected region length,
   - require lowered primitive evidence,
   - forbid tensor-array fallback, CPU fallback, and unexpected CPU materialization.
3. Confirm `layer_norm_small`, `rms_norm_small`, Metal `transformer_block_hot_path`, and `mlp_classifier_small` remain hard-gated.
4. Confirm CUDA `transformer_block_hot_path`, conv/pool, loss/index, and BOOL-producing compare targets remain visible-blocker expectations with stable expected reasons.
5. Add tests that fail if a `NATIVE_EXECUTABLE` target in `GpuTargetCoverageTruth` lacks a hard native/buffer expectation or if an unsupported target lacks expected visible reasons.

## Acceptance Criteria

- Reduction hot-path policy is no longer permissive after Phase 23 native execution closure.
- Supported target expectations forbid hidden tensor-array bridge and CPU fallback.
- Unsupported/capability-gated targets require visible reason evidence instead of silently passing with empty reports.
- Tests map policy behavior to `GpuTargetCoverageTruth` rather than comments or timing assumptions.

## Verification

```bash
./gradlew test --tests GpuHotPathCoverageTargetsTest --tests GpuCoverageSummaryTest
```

## Must Haves

- GPUCLOSE-01: Representative workloads have threshold policies aligned to actual v1.4 support state.
- GPUCLOSE-02: Supported target families cannot regress to tensor-array or CPU fallback without failing a deterministic gate.

## Threat Model

- **Threat:** A target remains in permissive partial mode after its family became native-executable.
  **Mitigation:** Tests cross-check supported target expectations against `GpuTargetCoverageTruth`.
- **Threat:** Unsupported targets are treated as passing without visible reason evidence.
  **Mitigation:** Tests require expected reason strings for capability-gated or unsupported target workloads.
