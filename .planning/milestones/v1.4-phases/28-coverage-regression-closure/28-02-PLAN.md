# Plan 28-02: Hard Gate Evaluation For Supported Families

**Phase:** 28 Coverage Regression Closure
**Requirements:** GPUCLOSE-01, GPUCLOSE-02
**Status:** Planned
**Wave:** 2
**Depends on:** 28-01

## Objective

Make supported v1.4 GPU families fail fast when runtime coverage regresses from native/buffer execution to tensor-array bridge, CPU fallback, shorter regions, lost lowered primitives, or hidden CPU materialization.

## Tasks

1. Add or tighten `GpuCoverageRegressionGateTest` cases for each supported target family:
   - reductions,
   - normalization,
   - Metal SDPA/transformer hot path,
   - MLP/fused epilogue path.
2. Add tests for suite-level `requireTargetsPass(...)` so missing target coverage summaries fail with target-specific context.
3. Add coverage fixtures that simulate:
   - lost native buffer binding,
   - tensor-array replay,
   - CPU fallback,
   - CPU materialization,
   - shortened selected region,
   - lost lowered primitive count,
   - lost fused subpattern count where expected.
4. Keep partial-blocker target tests separate: they must fail when expected visible reasons disappear, but should not require unsupported native coverage.
5. Verify failure messages remain stable enough for milestone audit and debugging.

## Acceptance Criteria

- A supported target cannot pass with tensor-array execution, CPU fallback, zero buffer-binding steps, or lost lowered primitives.
- A missing target coverage summary fails suite-level gate evaluation.
- Expected visible reasons are mandatory for unsupported/capability-gated targets.
- Failure strings identify the coverage dimension that regressed.

## Verification

```bash
./gradlew test --tests GpuCoverageRegressionGateTest --tests GpuHotPathCoverageTargetsTest --tests BenchmarkSuiteSessionTest
```

## Must Haves

- GPUCLOSE-02: Regression gates fail when a supported target family drops from native/buffer execution to tensor-array or CPU fallback.

## Threat Model

- **Threat:** Suite-level reports pass because one candidate had any accelerator data, even if the target workload lacks coverage.
  **Mitigation:** Require target-specific coverage summaries and fail missing summaries explicitly.
- **Threat:** Partial-blocker targets weaken hard gates for supported families.
  **Mitigation:** Keep supported and visible-blocker policies separate in tests and expectation construction.
