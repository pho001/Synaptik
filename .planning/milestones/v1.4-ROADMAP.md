## Milestone Rule

v1.4 closes only real execution gaps. A coverage row marked `SUPPORTED` must correspond to a backend-lowerable DAG primitive or backend-owned GPU sub-DAG that can execute without CPU materialization in a legal region. Stable rejection evidence is still allowed for unsupported semantics, but it does not count as closing native execution coverage.

## Phase Details

### Phase 22: Coverage Truth And Semantics Lock

**Goal:** Convert the current fallback list into source-of-truth operation-family contracts and measurable gates before changing backend behavior.

**Requirements:** GPUNATIVE-01, GPUNATIVE-02, GPUNATIVE-03

**Depends on:** v1.3 Phase 20 coverage reports/gates and current Metal/CUDA lowering matrix.

**Success Criteria:**
1. The current matrix identifies each listed family as native execution, tensor-array execution, CPU fallback, or unsupported rejection for Metal and CUDA.
2. Operation contracts define dtype, rank, layout, axis, keep-dims, broadcast, numerical tolerance, and backend capability requirements.
3. Representative workloads cover reductions, normalization, forward SDPA, loss/indexing, conv/pool, and BOOL compare outputs.
4. Existing reports/gates clearly separate native buffer execution from tensor-array bridge and CPU fallback.
5. Phase 23 can implement reductions without reopening semantics questions.

**Plans:**

Wave 1:
- [x] [22-01 Operation-Family Coverage Truth Table](v1.4-phases/22-coverage-truth-and-semantics-lock/22-01-PLAN.md) - classifies v1.4 target families by backend execution reality for GPUNATIVE-01/03.

Wave 2:
- [x] [22-02 Semantics Contracts For Target Families](v1.4-phases/22-coverage-truth-and-semantics-lock/22-02-PLAN.md) - locks dtype/rank/layout/axis/mask/index semantics for GPUNATIVE-02.

Wave 3:
- [x] [22-03 Representative Gate Baselines](v1.4-phases/22-coverage-truth-and-semantics-lock/22-03-PLAN.md) - establishes deterministic coverage baselines for GPUNATIVE-01/03.

### Phase 23: Forward Reductions Native Execution

**Goal:** Add `SUM`, `MEAN`, `REDUCE_MIN`, and `REDUCE_MAX` accelerator DAG representation and backend execution for supported Metal/CUDA paths.

**Requirements:** GPURED-01, GPURED-02, GPURED-03

**Depends on:** Phase 22.

**Success Criteria:**
1. `AcceleratorDagNodeType` and shared lowering encode forward reduction op kind, axis, and keep-dims semantics.
2. Metal executes supported reductions through MPSGraph reduction primitives without CPU materialization between internal GPU-region steps.
3. CUDA executes supported reductions through backend-owned kernels or a clearly capability-gated native path, not silent CPU replay.
4. Coverage matrix marks only actually executable reduction cases as supported and keeps unsupported dtype/layout/rank cases explicit.
5. Focused tests prove CPU parity, trace evidence, and device-owned handoff for reduction-heavy regions.

**Plans:**

Wave 1:
- [x] [23-01 Shared Forward Reduction DAG Contract](v1.4-phases/23-forward-reductions-native-execution/23-01-PLAN.md) - adds reduction DAG ABI, lowering, matrix, truth, and focused lowerer tests for GPURED-01.

Wave 2:
- [x] [23-02 Metal And CUDA Native Reduction Execution](v1.4-phases/23-forward-reductions-native-execution/23-02-PLAN.md) - adds backend execution for supported dense FLOAT32 reductions for GPURED-02/03.

Wave 3:
- [x] [23-03 Reduction Coverage Gates And Closure](v1.4-phases/23-forward-reductions-native-execution/23-03-PLAN.md) - updates fallback tests, coverage evidence, and phase state for GPURED-01/02/03.

### Phase 24: Normalization GPU Lowering

**Goal:** Lower `LAYER_NORM` and `RMS_NORM` to supported GPU-resident reduction-adjacent primitives/sub-DAGs.

**Requirements:** GPUNORMX-01, GPUNORMX-02, GPUNORMX-03

**Depends on:** Phase 23.

**Success Criteria:**
1. Layer norm and RMS norm have backend-neutral lowering contracts covering epsilon, axis set, gamma/beta, and output shape.
2. Metal/CUDA execute supported normalization flows through GPU sub-DAGs using reductions and elementwise primitives.
3. Unsupported normalized-shape, dtype, or layout cases report stable rejection details.
4. Normalization workloads reduce CPU materialization boundaries against v1.3 evidence.
5. CPU parity tests cover representative normalization shapes and numerical tolerance.

**Plans:**

Wave 1:
- [x] [24-01 Shared Normalization DAG Contract](v1.4-phases/24-normalization-gpu-lowering/24-01-PLAN.md) - expands `LAYER_NORM` and `RMS_NORM` into backend-neutral reduction/elementwise GPU DAGs for GPUNORMX-01/02.

Wave 2 *(blocked on Wave 1 completion)*:

Wave 3 *(blocked on Waves 1-2 completion)*:
- [x] [24-03 Planner Admission And Coverage Matrix Update](v1.4-phases/24-normalization-gpu-lowering/24-03-PLAN.md) - moves legal normalization rows from fallback to supported while preserving stable rejection cases for GPUNORMX-01/02/03.

Wave 4 *(blocked on Waves 1-3 completion)*:

### Phase 25: Forward SDPA Semantic Enablement

**Status:** Complete - verified 2026-05-01

**Goal:** Verify and admit forward SDPA for supported scale/mask/rank/dtype cases, with explicit rejection for unsupported cases.

**Requirements:** GPUSDPA-01, GPUSDPA-02, GPUSDPA-03

**Depends on:** Phase 22 and Phase 23.

**Success Criteria:**
1. Forward SDPA semantics are locked for scale, rank, mask/no-mask, dtype, and backward-pass interaction.
2. Metal direct SDPA is enabled only for verified MPSGraph primitive-DAG semantics and capability.
3. CUDA either gains supported SDPA lowering/native execution or a precise required-capability rejection that does not masquerade as support.
4. Transformer attention coverage gates prove backend execution path and CPU exit count.
5. Numerical tests cover masked and unmasked supported cases.

**Plans:**

Wave 3 *(blocked on Wave 1 completion)*:
- [x] [25-03 CUDA Forward SDPA Support-Or-Rejection Contract](v1.4-phases/25-forward-sdpa-semantic-enablement/25-03-PLAN.md) - keeps CUDA direct SDPA as stable `CAPABILITY_MISSING` fallback with mask/dtype/layout diagnostics for GPUSDPA-02/03.

### Phase 26: Loss-Adjacent And Indexing GPU Coverage

**Status:** Complete - verified 2026-05-02

**Goal:** Expand supported loss-adjacent and gather/scatter/index paths without hiding duplicate-index, ignore-index, or dtype limitations.

**Requirements:** GPULOSSIDX-01, GPULOSSIDX-02, GPULOSSIDX-03

**Depends on:** Phase 23 and Phase 25.

**Success Criteria:**
1. Loss-adjacent target flows have explicit GPU lowering or stable rejection per dtype/index semantics.

4. Coverage reports show whether indexing/loss flows stayed on GPU or exited to CPU.
5. Unsupported combinations do not shorten adjacent supported GPU regions without visible reason.

### Phase 27: Conv Pool And Bool Compare Outputs

**Goal:** Add GPU coverage for conv/pool targets and device-resident BOOL compare outputs feeding masks/where consumers.

**Requirements:** GPUCONVBOOL-01, GPUCONVBOOL-02, GPUCONVBOOL-03

**Depends on:** Phase 22 and Phase 23.

**Success Criteria:**
1. Conv/pool target contracts define supported layout, rank, stride, padding, dilation, and dtype cases.
2. Supported compare operations produce device-resident BOOL outputs that can feed `WHERE` or mask consumers.
3. Metal/CUDA expose backend-specific execution or capability-gated rejection for conv/pool paths.
4. Coverage reports show selected region length, lowered primitive count, backend path, and CPU exits.
5. CPU parity tests cover compare-output masks and at least one representative conv/pool workload.

**Plans:**

Wave 1:

Wave 2:
- [x] [27-02 Bool Compare Output Residency And WHERE Boundary Evidence](v1.4-phases/27-conv-pool-and-bool-compare-outputs/27-02-PLAN.md) - proves external BOOL predicate residency versus native BOOL-producing compute boundaries.

Wave 3:
- [x] [27-03 Conv Pool Support-Or-Rejection Contract](v1.4-phases/27-conv-pool-and-bool-compare-outputs/27-03-PLAN.md) - adds representative conv/pool planner diagnostics, parity baselines, and capability-gated rejection evidence.

Wave 4:
- [x] [27-04 Coverage Gates And Documentation Closure](v1.4-phases/27-conv-pool-and-bool-compare-outputs/27-04-PLAN.md) - closes report/docs/verification evidence for GPUCONVBOOL-01/02/03.

### Phase 28: Coverage Regression Closure

**Status:** Complete - verified 2026-05-02

**Goal:** Prove v1.4 reduced CPU exits on representative workloads and harden regression gates against hidden fallback.

**Requirements:** GPUCLOSE-01, GPUCLOSE-02, GPUCLOSE-03

**Depends on:** Phases 23-27.

**Success Criteria:**
1. Representative transformer, normalization, loss/indexing, and conv/pool workloads have before/after coverage evidence.
2. Gates fail when a supported family regresses from native/buffer execution to tensor-array or CPU fallback.
3. Reports include fallback count, CPU materialization count, region length, lowered primitive count, and backend execution path.
4. Local benchmark/calibration/profile artifacts remain unstaged unless intentionally promoted to fixtures.
5. Milestone audit can verify every v1.4 requirement from checked-in tests, docs, and reports.

**Plans:**

Wave 1:
- [x] [28-01 Target Coverage Policy Audit](v1.4-phases/28-coverage-regression-closure/28-01-PLAN.md) - aligns v1.4 hot-path policies with target coverage truth so supported families get hard gates and unsupported families require visible reasons.

Wave 2 *(blocked on Wave 1 completion)*:

Wave 3 *(blocked on Waves 1-2 completion)*:
