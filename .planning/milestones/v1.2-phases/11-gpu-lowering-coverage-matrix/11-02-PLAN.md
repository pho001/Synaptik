<objective>
Make Metal and CUDA planner legality consume the shared coverage matrix while preserving backend-specific dtype, layout, native capability, and semantic rejection rules.
</objective>

<source_audit>
GOAL: Aligns backend allowlists with the shared Phase 11 matrix.
REQ GPULOWER-01: Planner adapters are now checked against the matrix that documents supported/fallback/unsupported coverage.
REQ GPULOWER-03: Metal and CUDA expose stable rejection reasons for unsupported operation, dtype, layout, and capability gaps.
D-05: Covered by reusing the current shared accelerator DAG and backend legality adapters rather than introducing a second lowering architecture.
D-07: Covered by making Metal and CUDA consult the shared coverage matrix.
D-08: Covered by preserving backend-owned dtype, external input role, SDPA semantic, runtime capability, and layout gates.
D-09: Covered by stable planner unsupported reason fragments from the shared reason enum.
D-10: Covered by keeping public `Tensor` untouched and leaving residency in existing runtime state.
D-11: Covered by explicit CUDA direct non-dense rejection tests and reason text.
D-12: Covered by support decisions that still depend on backend assignment, dtype, layout, runtime enablement, and cost/capability contracts.
D-13: Covered by focused Metal/CUDA legality adapter tests.
D-15: Covered by tests for both matrix-supported and visibly rejected candidates.
</source_audit>

<threat_model>
T-11-03: Divergent Metal/CUDA allowlists could make docs and planner behavior disagree. Mitigation: adapters must consult `GpuLoweringCoverageMatrix.isSupported(...)` before backend-specific gates.
T-11-04: CUDA could broaden lowering into arbitrary non-dense layouts. Mitigation: keep layout legality conservative and test direct non-dense rejection with stable reason wording.
</threat_model>
