<objective>
Create the backend-neutral GPU lowering coverage matrix and stable reason-code model that classify Metal and CUDA operation families as supported, fallback, or unsupported.
</objective>

<source_audit>
GOAL: Covers the checked-in coverage matrix required by Phase 11.
REQ GPULOWER-01: Adds source-level and documentation matrix entries for Metal/CUDA operation coverage.
REQ GPULOWER-03: Defines stable reason codes for unsupported operations, dtype, layout, shape/rank, capability, ABI mismatch, and deferred fused-region support.
D-01: Covered by the checked-in Metal/CUDA matrix with supported/fallback/unsupported statuses and non-supported reason codes.
D-02: Covered by required rows for matmul/linear, elementwise chains, reductions, softmax/log-softmax-style flows, normalization, layout/view-adjacent nodes, and loss-adjacent operations.
D-03: Covered by source-level matrix classes plus docs drift tests.
D-06: Covered by explicit matrix-first fallback/unsupported rows for reductions, normalization, and loss-adjacent families.
D-07: Covered by backend-neutral coverage classes under `backend.accelerator.lowering`.
D-08: Covered by keeping the shared model semantic while backend capability checks stay in Metal/CUDA code.
D-09: Covered by `GpuLoweringUnsupportedReason` values for unsupported operation, dtype, layout, rank/shape, capability, native ABI mismatch, and deferred fused-region support.
</source_audit>

<threat_model>
T-11-01: The coverage matrix could overclaim support and hide CPU fallback. Mitigation: require every non-supported entry to carry a stable `GpuLoweringUnsupportedReason` and every supported entry to name the operation family.
T-11-02: Documentation could drift from the executable source matrix. Mitigation: add tests that assert required docs phrases, statuses, and reason codes for each required Phase 11 family.
</threat_model>
