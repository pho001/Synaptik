<objective>
Expand the highest-value safe lowering path by supporting `LOG_SOFTMAX` through existing accelerator DAG primitives and add selected/rejected candidate tests for longer GPU regions.
</objective>

<source_audit>
GOAL: Broadens operation lowering without adding unsafe native ABI claims.
REQ GPULOWER-02: Supported matmul/linear, elementwise, layout-adjacent, and softmax-ish paths can remain in GPU regions when contracts allow.
REQ GPULOWER-03: Rejected reduction, normalization, loss-adjacent, dtype, layout, and capability gaps remain visible.
D-04: Covered by prioritizing `linear/matmul -> layout/view -> softmax-ish` paths over isolated low-impact ops.
D-05: Covered by adding `LOG_SOFTMAX` through existing DAG primitives instead of a parallel lowering architecture.
D-06: Covered by keeping reductions, normalization, and loss-adjacent families rejected with matrix entries unless a narrow safe implementation exists.
D-11: Covered by preserving conservative CUDA layout behavior in selected/rejected tests.
D-12: Covered by prepared-selection tests that require dtype, layout, runtime enablement, cost, and capability contracts before GPU selection.
D-13: Covered by shared lowerer, Metal/CUDA legality, and prepared-execution tests.
D-15: Covered by one newly supported `LOG_SOFTMAX` path and rejected reduction/normalization/loss-adjacent paths.
</source_audit>

<threat_model>
T-11-05: Adding `LOG_SOFTMAX` as a new native ABI code could break Metal/CUDA stubs. Mitigation: lower it as a DAG decomposition using existing `SOFTMAX` and `LOG` node types.
T-11-06: Selected-candidate tests could prove only lowerer internals and miss backend selection behavior. Mitigation: add prepared-execution tests that assert selected and rejected candidates in prepare trace.
</threat_model>
