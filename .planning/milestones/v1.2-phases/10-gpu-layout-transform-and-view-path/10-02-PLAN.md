<objective>
Propagate metadata-only layout/view nodes as device-owned bindings before CPU materialization, using backend-specific alias bindings for Metal and CUDA while preserving existing CPU fallback behavior for unsupported layouts.
</objective>

<source_audit>
GOAL: Covers device-resident metadata-only views for reshape, permute, expand, alias-like operations, and legal view-like graph values.
REQ GPUVIEW-01: View-like graph values can remain device-resident through binding propagation.
REQ GPUVIEW-02: CPU materialization is avoided between compatible accelerator nodes.
REQ GPUVIEW-03: Metal/CUDA share the common decision contract while backend handles remain backend-owned.
</source_audit>

<threat_model>
T-10-03: Alias bindings could double-own native handles and destroy buffers too early. Mitigation: `viewOf(...)` creates a new binding record around the same handle but registers no new `ExecutionResource`.
T-10-04: CPU-owned layout steps could materialize source device data before propagation. Mitigation: `DeviceLayoutViewPropagator` runs before `requireCpuReadableInputs(...)` and skips CPU execution only after attaching a valid target binding.
</threat_model>
