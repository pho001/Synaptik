<objective>
Add a capability-gated dense GPU materialization path for `contiguous()` and non-contiguous-source `reshape`, so supported Metal and CUDA flows can convert view metadata into dense device buffers without a Java array round trip.
</objective>

<source_audit>
GOAL: Covers GPU-side layout transform/materialization, not arbitrary downstream operation lowering.
REQ GPUVIEW-01: `contiguous` and non-contiguous reshape receive a GPU materialization request/decision path.
REQ GPUVIEW-02: Supported transforms produce CPU-parity outputs and avoid intermediate CPU materialization.
REQ GPUVIEW-03: Metal and CUDA expose backend-specific transform implementations behind shared layout transform decisions.
</source_audit>

<threat_model>
T-10-05: Native layout transform symbols could break older Metal/CUDA libraries. Mitigation: make symbols optional and disable only dense GPU materialization when absent.
T-10-06: A dense transform could copy using logical bytes while ignoring physical spans, corrupting strided or offset views. Mitigation: pass shape, strides, storage offset, logical element count, and physical span from `AcceleratorLayoutAbiV2Descriptor`, and test permuted plus broadcast inputs.
</threat_model>
