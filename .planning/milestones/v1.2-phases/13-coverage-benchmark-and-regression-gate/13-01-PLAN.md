<objective>
Add the backend-neutral GPU coverage metric contract and render it in per-workload text and JSON benchmark reports without removing existing accelerator trace fields.
</objective>

<source_audit>
GOAL: Makes Phase 13 coverage evidence measurable from existing prepare/run traces before workload comparisons or gates depend on it.
REQ GPUCOV-01: Covered by `GpuCoverageSummary` fields and renderer assertions.
REQ GPUCOV-03: Partially covered by stable schema that later gates consume.
D-01 through D-03 and D-08: Covered by backend-neutral summary fields, path distinctions, and fallback reason counts.
</source_audit>

<threat_model>
T-13-01: A report could claim GPU coverage because an accelerator backend appears once, while most work ran on CPU. Mitigation: `gpuCoverageRatio` must be computed as accelerator-buffer steps divided by total traced run steps.
T-13-02: Tensor-array bridge execution could be counted as native GPU buffer coverage. Mitigation: summary must expose `tensorArrayStepCount` separately from `bufferBindingStepCount`.
T-13-03: Selected/rejected candidate reasons could be lost when rendering a compact report. Mitigation: summary must include `selectedRegionCount`, `maxSelectedRegionLength`, `averageSelectedRegionLength`, and `rejectedCandidateReasonCounts`.
T-13-04: CPU materialization boundaries and device handoffs could remain hidden. Mitigation: summary must include materialization reason counts, bytes, duration, storage residency counts, and device handoff count.
</threat_model>

  <action>
    Add `src/main/java/tuning/benchmark/report/GpuCoverageSummary.java` as a Java record with:
    - `Map<String, BackendCoverage> backends`

    Add nested record `BackendCoverage` with exact fields:
    - `int totalStepCount`
    - `int acceleratorStepCount`
    - `double gpuCoverageRatio`
    - `int selectedRegionCount`
    - `int maxSelectedRegionLength`
    - `double averageSelectedRegionLength`
    - `int rejectedCandidateCount`
    - `Map<String, Integer> rejectedCandidateReasonCounts`
    - `int bufferBindingStepCount`
    - `int tensorArrayStepCount`
    - `int cpuFallbackStepCount`
    - `int fallbackCount`
    - `int cpuMaterializationCount`
    - `Map<String, Integer> cpuMaterializationReasonCounts`
    - `long cpuMaterializationBytes`
    - `long cpuMaterializationDurationNs`
    - `long copyDurationNs`
    - `int deviceHandoffCount`
    - `Map<String, Integer> storageResidencyCounts`
    - `List<String> reasonCodes`
    - `List<String> fallbackReasons`

    Add static factories:
    - `GpuCoverageSummary fromTrace(graph.execution.trace.ExecutionTrace trace)`
    - `boolean present()`

    Derivation rules:
    - Backend keys come from `acceleratorBufferBackend`, step `backend`, selected backend decisions, and CPU materialization `materializedFrom`.
    - `gpuCoverageRatio = acceleratorStepCount / totalStepCount`, with `0.0d` when `totalStepCount == 0`.
    - `acceleratorStepCount` counts steps whose metadata has `acceleratorBufferBackend` for that backend.
    - `bufferBindingStepCount`, `tensorArrayStepCount`, and `cpuFallbackStepCount` come from `acceleratorBufferExecutionPath` values `BUFFER_BINDING`, `TENSOR_ARRAY`, and `CPU_FALLBACK`.
    - `fallbackCount = tensorArrayStepCount + cpuFallbackStepCount`.
    - Selected region metrics come from selected `BackendSelectionDecisionTrace` rows whose `selectedBackend().name()` matches the backend.
    - Rejected reason counts come from unselected backend decisions where `compatibleBackends` contains that backend or the selected backend is that backend; blank reasons become `unspecified`.
    - CPU materialization metrics count traces whose `materializedFrom` equals the backend.
    - `copyDurationNs = acceleratorJavaToNativeCopyNs + acceleratorNativeToJavaCopyNs + acceleratorNativeDeviceCopyNs`, falling back to Metal-specific copy keys when generic keys are absent.
    - `deviceHandoffCount` counts adjacent run-step backend transitions where either side equals the backend and the backend value changes, plus CPU materialization traces from that backend.
    - `storageResidencyCounts` counts nonblank `storageResidency` metadata values from that backend's accelerator steps.
  </action>
