# Plan 29-01: Metal DType Capability Model And Reason Codes

**Phase:** 29 Metal DType ABI And Capability Truth
**Requirements:** METALDTYPE-01, METALDTYPE-03
**Status:** Planned
**Wave:** 1

## Objective

Replace coarse Metal dtype booleans with an explicit capability decision model that separates storage representability, external input legality, compute legality, output legality, and per-operation dtype support.

## Tasks

1. Add a Metal dtype support model with stable roles and reason codes:
   - storage representation,
   - external input,
   - external input role,
   - compute,
   - output,
   - operation-specific dtype support.
2. Update `MetalMpsCapabilities` to expose detailed decisions for all `DataType` values:
   - `FLOAT32` supported for storage, external input, compute, output, and current supported op families;
   - `BOOL` supported for storage and current predicate input roles only;
   - `BFLOAT16` and `INT32` representable where runtime storage can carry them, but unsupported for Metal native compute/output in this phase;
   - `FLOAT64` explicitly unsupported for Metal native compute/output.
3. Keep existing `supportsComputeDType`, `supportsOutputDType`, `supportsExternalInputDType`, `supportsExternalInputRole`, and `abiDataTypeCode` methods as compatibility wrappers.
4. Ensure unsupported messages include role, dtype, and stable reason code.
5. Add focused unit tests for the role matrix and current operation-specific cases (`WHERE`, unmasked SDPA, default numeric ops).

## Acceptance Criteria

- Every `DataType` has an explicit Metal decision for storage, external input, compute, and output.
- Operation-specific decisions do not imply BF16, BOOL output, INT32, or FLOAT64 execution.
- Existing callers keep compiling through compatibility wrappers.
- Tests lock current truth and fail if a future broadening accidentally bypasses explicit decisions.

./gradlew test --tests MetalMpsCapabilitiesTest

## Must Haves

- METALDTYPE-01: Metal capability probing distinguishes dtype roles and operation-specific support.
- METALDTYPE-03: Dtype fallback reasons are stable and diagnosable.

## Threat Model

- **Threat:** Dtype residency is mistaken for native compute support.
  **Mitigation:** Separate role decisions and tests for BF16, INT32, BOOL, and FLOAT64.
- **Threat:** Existing callers drift because booleans are removed.
  **Mitigation:** Preserve boolean wrappers over the new model.
