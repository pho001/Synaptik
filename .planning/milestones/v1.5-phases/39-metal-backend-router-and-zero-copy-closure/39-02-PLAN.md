# Plan 39-02: Custom Kernel Integration Point And MPSGraph Routing

**Phase:** 39 Metal Backend Router And Zero-Copy Closure
**Requirements:** METALROUTER-01
**Status:** Complete
**Wave:** 2
**Depends on:** 39-01

## Objective

Add a narrow custom Metal kernel route seam while keeping MPSGraph as the default supported route for existing operation coverage.

## Tasks

1. Add a custom-kernel SPI under `src/main/java/backend/metal/kernel/`:
   - `MetalCustomKernelBridge`
   - `MetalCustomKernelExecutable`
   - `MetalCustomKernelCapabilities`
   - unavailable implementation with stable reason text
2. Add a router adapter that evaluates custom-kernel eligibility from lowered primitives and manifest family metadata.
3. Keep initial `CUSTOM_KERNEL` support capability-gated unless a safe scoped kernel is implemented during execution.
4. Ensure `MPS_GRAPH` remains selected for existing supported native paths.
5. Add tests proving:
   - custom-kernel unavailable reason appears in rejected route evidence;
   - required-mode unsupported custom route does not silently fall back;
   - MPSGraph execution path still produces parity and native buffer evidence.

## Acceptance Criteria

- `src/main/java/backend/metal/kernel/MetalCustomKernelBridge.java` exists and does not depend on public `Tensor` device APIs.
- Router rejected-route evidence includes `CUSTOM_KERNEL_UNAVAILABLE` when no custom kernel bridge is available.
- Existing MPSGraph lowering tests still pass without route changes.
- No CPU `Operation.OpType.FUSED` or CPU fused ASM path is reused by the custom-kernel seam.

./gradlew test --tests GpuCoverageRegressionGateTest --tests GpuHotPathCoverageTargetsTest

## Threat Model

- **Threat:** A placeholder custom-kernel route falsely claims GPU execution or hides MPSGraph fallback.
  **Mitigation:** `CUSTOM_KERNEL` must stay rejected with explicit capability evidence until real native execution and parity tests exist.
