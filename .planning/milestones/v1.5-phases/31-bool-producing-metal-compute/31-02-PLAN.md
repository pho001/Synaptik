# Plan 31-02: Native Compare Logical And BOOL Reduction Execution

**Phase:** 31 BOOL-Producing Metal Compute
**Requirements:** METALBOOL-01, METALBOOL-03
**Status:** Complete
**Wave:** 2

## Objective

Implement native Metal execution for scoped BOOL-producing compare/logical operations and make a deliberate support-or-reject decision for `REDUCE_ALL` and `REDUCE_ANY`.

## Tasks

1. Extend the Objective-C MPSGraph shim to emit BOOL outputs for compare nodes.
2. Add native branches for `LOGICAL_AND`, `LOGICAL_OR`, and `LOGICAL_NOT` if MPSGraph exposes stable logical BOOL ops on the local SDK.
3. Add or reject `REDUCE_ALL` and `REDUCE_ANY` with explicit rank/axis/keepDims reason codes.
4. Update `MetalMpsFfmBridge` and buffer validation to permit BOOL outputs for executables whose output dtype is BOOL.
5. Add native `metalTest` coverage for compare output readback and any supported logical/reduction subset.
6. Preserve stable fallback/rejection tests for BOOL ops not yet admitted.

## Acceptance Criteria

- Supported compare ops execute through `BUFFER_BINDING` and return exact BOOL bytes.
- Supported logical ops, if admitted, match CPU truth tables.
- `REDUCE_ALL` and `REDUCE_ANY` are either native with parity or rejected with stable explicit reasons.
- Native tests skip cleanly when the Metal shim/runtime lacks required capability.

## Verification

```bash
./gradlew test --tests backend.metal.bridge.MetalMpsFfmBridgeTest --tests backend.metal.MetalMpsCapabilitiesTest

git diff --check
```

## Threat Model

- **Threat:** BOOL output byte layout differs between MPSGraph and Synaptik.
  **Mitigation:** Assert exact raw BOOL output bytes in native tests.
- **Threat:** Reduction identity semantics are wrong.
  **Mitigation:** Keep reductions rejected unless CPU parity covers axis, keepDims, and edge cases.
